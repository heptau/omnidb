Rollen und Berechtigungen

Der Bereich Berechtigungen ist ein Browser für Rollen und Privilegien in PostgreSQL. Er stellt die Rollen eines Servers im Finder-Stil in nebeneinanderliegenden Spalten dar: Wählen Sie links eine Rolle, und die Spalten rechts davon zeigen, wovon sie Mitglied ist, wer Mitglied von ihr ist und was sie auf jedem Datenbankobjekt tatsächlich tun darf — einschließlich allem, was sie nur indirekt besitzt, über geerbte Rollenmitgliedschaften oder über PUBLIC. Rollen, Mitgliedschaften und Privilegien lassen sich direkt dort anlegen, ändern und entziehen.

Hinweis: Dieser Bereich unterstützt derzeit nur PostgreSQL. Für jede andere Verbindung zeigt er Berechtigungen werden für … noch nicht unterstützt. / Derzeit wird nur PostgreSQL unterstützt.

Den Bereich öffnen

Klicken Sie in der linken Leiste auf das Symbol Berechtigungen (das Personensymbol). Der Bereich arbeitet mit einer Verbindung, die bereits im Bereich Datenbank geöffnet ist: Oben wird dieselbe Leiste der geöffneten Verbindungs-Tabs angezeigt, und der Bereich verwendet den dort ausgewählten Verbindungs-Tab. Ist keine Verbindung geöffnet, zeigt er Keine Verbindung geöffnet — öffnen Sie zuerst eine (siehe Datenbanken verwalten). Die Spalten werden bei jedem Betreten des Bereichs neu aufgebaut, eine frühere Auswahl wird also zurückgesetzt.

Alles, was Sie hier tun, erfordert dieselben Privilegien wie das entsprechende SQL (CREATEROLE, Superuser oder Eigentümerschaft am Objekt, je nach Aktion) — OmniDB führt die Anweisungen mit den Zugangsdaten der verwendeten Verbindung aus.

Spalte 1: Rollen

Die Spalte Rollen listet alle Rollen des Servers auf, einschließlich der eingebauten pg_*-Rollen, sortiert nach Namen. Rollen, die sich anmelden können (Benutzer), haben ein Symbol mit einer Person; Rollen, die das nicht können (Gruppen), ein Symbol mit zwei Personen. Die erste Zeile ist immer PUBLIC (Globussymbol) — keine echte Rolle, sondern die Pseudorolle, der jede Rolle implizit angehört, sodass an PUBLIC vergebene Privilegien auf dieselbe Weise angezeigt und bearbeitet werden können.

Klicken Sie auf eine Rolle, um sie zu fokussieren; die übrigen Spalten zeigen dann diese Rolle. Unter der Liste:

  • + öffnet den Dialog Rolle erstellen: Rollenname, Passwort und die Attribut-Kontrollkästchen Kann sich anmelden (standardmäßig aktiviert), Superuser, Kann Datenbanken erstellen, Kann Rollen erstellen, Erbt die Privilegien der Rollen, deren Mitglied sie ist (standardmäßig aktiviert), Kann Replikation starten und Umgeht die Sicherheit auf Zeilenebene (RLS), dazu Verbindungslimit (-1 = unbegrenzt) und Konto läuft ab (leer lassen für unbegrenzte Gültigkeit).
  • − löscht die ausgewählte Rolle (für PUBLIC deaktiviert).

Ein Rechtsklick auf eine Rolle (nicht PUBLIC) bietet:

  • Passwort ändern — fragt zweimal nach dem neuen Passwort. Das Passwort wird vor dem Senden in dem Format gehasht, für das der Server selbst konfiguriert ist (SCRAM-SHA-256 oder md5).
  • Attribute ändern — dieselben Attributfelder wie bei Rolle erstellen, vorbelegt mit den aktuellen Werten der Rolle. Wird Konto läuft ab geleert, entfällt das Ablaufdatum.
  • Rolle löschen — fragt Rolle „…“ löschen? Dies kann nicht rückgängig gemacht werden. und führt dann ein einfaches DROP ROLE aus; PostgreSQL verweigert dies, solange die Rolle noch Objekte besitzt oder Privilegien hält.

Spalte 2: Mitgliedschaften

Die zweite Spalte ist in zwei Hälften geteilt:

  • … — Mitglieder (oben): die Rollen, die Mitglied der fokussierten Rolle sind.
  • … — Mitglied von (unten): jede Rolle, der die fokussierte Rolle angehört, direkt oder über andere Rollen, zu einer einzigen Liste zusammengeführt. PUBLIC steht immer an erster Stelle.

In beiden Hälften werden direkte Mitgliedschaften in normaler Schrift und indirekte (geerbte) ausgegraut dargestellt. Eine direkte Mitgliedschaft, die WITH ADMIN OPTION vergeben wurde, ist mit (Admin-Option) gekennzeichnet. Für PUBLIC zeigen beide Hälften nur PUBLIC ist kein Mitglied einer Rolle.

  • Das + unter Mitglied von öffnet Mitgliedschaft gewähren: Wählen Sie eine Rolle, deren Mitglied die fokussierte Rolle werden soll, optional Mit Admin-Option (Mitgliedschaft weitergeben).
  • Das + unter Mitglieder öffnet Mitglied hinzufügen: derselbe Dialog in umgekehrter Richtung — die gewählte Rolle wird Mitglied der fokussierten Rolle.
  • − (oder Rechtsklick → Mitgliedschaft entfernen) entzieht eine Mitgliedschaft nach der Rückfrage Mitgliedschaft in „…“ entziehen?. Nur direkte Mitgliedschaften lassen sich entfernen; eine geerbte muss dort entzogen werden, wo sie tatsächlich vergeben wurde.
  • Ein Doppelklick auf eine Zeile oder Rechtsklick → Als aktive Rolle festlegen macht diese Rolle zur fokussierten, genau als hätten Sie sie in der Spalte Rollen angeklickt — der schnellste Weg, einer Vererbungskette nach oben zu folgen.

Spalte 3: Objekte und effektive Privilegien

Die dritte Spalte, … — Objekte, ist ein Baum aller Objekte, auf die die fokussierte Rolle irgendein Privileg hat — ihre effektiven Privilegien: ihre eigenen direkten Grants plus alles, was sie über ihre Mitgliedschaften und über PUBLIC erbt. Er beginnt mit zwei Gruppen, Datenbanken (alle Datenbanken des Servers) und Tablespaces; ein Knoten wird normal dargestellt, wenn die Rolle dort ein Privileg hat, andernfalls ausgegraut.

Beim Aufklappen einer Datenbank werden deren Objekte über eine separate Verbindung zu dieser Datenbank geladen (die aktive Datenbank des Verbindungs-Tabs ändert sich nicht): Schemas und innerhalb jedes Schemas Ordner für Tabellen, Ansichten, Sequenzen, Funktionen, Prozeduren, materialisierte Ansichten, Typen und Domänen; Foreign Data Wrappers und Fremdserver liegen direkt unter der Datenbank. Aufgeführt werden nur Objekte, auf die die Rolle tatsächlich ein Privileg hat (Systemschemas werden ausgelassen); ein ausgegrautes Schema erscheint nur, weil etwas darin enthalten ist. Gibt es überhaupt nichts, zeigt die Datenbank Keine Privilegien für Objekte in dieser Datenbank.

Privilegien bearbeiten

Klicken Sie mit der rechten Maustaste auf eine Datenbank, einen Tablespace, ein Schema oder ein Objekt und wählen Sie Privilegien bearbeiten. Der Dialog listet jedes für diese Objektart gültige Privileg als Kontrollkästchen auf:

  • Datenbank: CREATE, CONNECT, TEMPORARY; Tablespace: CREATE; Schema: CREATE, USAGE;
  • Tabelle, Ansicht und materialisierte Ansicht: SELECT, INSERT, UPDATE, DELETE, TRUNCATE, REFERENCES, TRIGGER;
  • Sequenz: USAGE, SELECT, UPDATE; Funktion und Prozedur: EXECUTE; Typ, Domäne, Foreign Data Wrapper und Fremdserver: USAGE.

Jedes Kontrollkästchen zeigt, woher das Privileg stammt:

  • angekreuzt — die Rolle besitzt es direkt; entfernen Sie das Häkchen, um es per REVOKE zu entziehen;
  • angekreuzt, aber deaktiviert, mit Geerbt von: … — die Rolle hat es nur über eine andere Rolle oder PUBLIC. Es kann hier nicht entzogen werden; machen Sie die Quellrolle aktiv (Als aktive Rolle festlegen) und entziehen Sie es dort;
  • nicht angekreuzt — die Rolle hat es nicht; setzen Sie das Häkchen, um es direkt per GRANT zu vergeben.

Mit Grant-Option (Privileg weitergeben) gilt für die Privilegien, die Sie in diesem Dialog neu vergeben. Bestätigen Sie mit der Hauptschaltfläche des Dialogs, die mit dem Namen des Objekts beschriftet ist.

Um etwas auf einem Objekt zu vergeben, das noch nicht im Baum steht, verwenden Sie das + (Objektprivileg hinzufügen) unter der Spalte: Wählen Sie den Objekttyp, dann die Datenbank (für alles außer Datenbanken und Tablespaces; voreingestellt ist die aktuelle Datenbank der Verbindung), das Schema für Objekte auf Schemaebene, das Objekt selbst (Funktionen werden mit ihrer Argumentsignatur angezeigt), kreuzen Sie die Privilegien an und optional Mit Grant-Option (Privileg weitergeben).

Wenn Sie in der ersten Spalte PUBLIC auswählen, können Sie bearbeiten, was PUBLIC selbst gewährt ist (GRANT … TO PUBLIC / REVOKE … FROM PUBLIC).

Wichtig: Jede Aktion in diesem Bereich wird sofort auf dem Server ausgeführt — es gibt keine SQL-Vorschau und kein Rückgängigmachen. Nur Rolle löschen und Mitgliedschaft entfernen fragen vorher nach einer Bestätigung. Lehnt der Server eine Anweisung ab, wird seine Fehlermeldung angezeigt.
