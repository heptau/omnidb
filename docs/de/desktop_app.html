Desktop-App

Die Desktop-App (OmniDB.app unter macOS, OmniDB/OmniDB.exe unter Linux und Windows) ist ein kleines natives Fenster um dieselbe OmniDB-Oberfläche, die die Server-Version an Browser ausliefert. Sie startet im Hintergrund eine eigene, private Instanz von omnidb-server, die nur auf dem lokalen Rechner lauscht, und meldet Sie automatisch als eingebauten Benutzer admin an — es gibt keine Anmeldeseite, kein Symbol Konto und nichts zu konfigurieren. Wie Sie die App erhalten, steht im Kapitel Installation.

Wo die Daten liegen

Gespeicherte Verbindungen, Snippets, Einstellungen, der Abfrageverlauf usw. werden in ~/.omnidb/omnidb-app/ abgelegt (die Benutzerdatenbank omnidb.db sowie ein Ordner temp für Exporte und die gespeicherte Fensterposition). Um einen separaten Datenbestand zu verwenden — etwa einen Wegwerf-Bestand zum Testen — starten Sie die App mit einem anderen Home-Verzeichnis:

open -a OmniDB --args -d /path/to/other/dir    # macOS
./OmniDB -d /path/to/other/dir                  # Linux
OmniDB.exe -d C:\path\to\other\dir              # Windows

Das Verzeichnis muss bereits existieren; ein neues, leeres Verzeichnis wird bei der ersten Verwendung automatisch eingerichtet. Gespeicherte Passwörter werden mit einem Schlüssel verschlüsselt, der im Geheimnisspeicher des Betriebssystems liegt — siehe Sicherheit und Mehrbenutzer-Server.

Die Menüleiste

  • OmniDB: Über OmniDB, Einstellungen… (Cmd/Ctrl-,), Daten aus vorheriger Installation importieren… (nur im sandboxed macOS-Build, siehe unten) und OmniDB beenden (Cmd/Ctrl-Q).
  • Bearbeiten und Fenster: die Standardmenüs des Betriebssystems (Rückgängig/Ausschneiden/Kopieren/Einfügen, Minimieren, Zoomen, Vollbild, …).
  • Ansicht: springt zu einem Bereich der linken Leiste — Willkommen (Cmd/Ctrl-Shift-W), Verbindungen (Cmd/Ctrl-Shift-C), Datenbank (Cmd/Ctrl-Shift-D), Benachrichtigungen (Cmd/Ctrl-Shift-N), Verbundene Benutzer (Cmd/Ctrl-Shift-U), Snippets (Cmd/Ctrl-Shift-S) — sowie Datenbankbaum ein-/ausblenden (Cmd/Ctrl-B) und Eigenschaften/DDL-Bereich ein-/ausblenden (Cmd/Ctrl-Shift-B).
  • Hilfe: Erste Schritte (das interaktive Tutorial), Tastenkombinationen (öffnet die Einstellungen in der Kategorie Tastenkombinationen), omnidb.net besuchen und GitHub-Repository.

Die Menüs OmniDB, Ansicht und Hilfe werden in der Sprache angezeigt, die unter Einstellungen > Erscheinungsbild > Sprache gewählt ist, und wechseln sofort, wenn Sie sie ändern; bevor die erste Seite geladen ist, folgen sie der Sprache des Betriebssystems. Die Standardmenüs Bearbeiten und Fenster bleiben englisch. Der Fenstertitel zeigt den Bereich, in dem Sie sich befinden (zum Beispiel OmniDB - Snippets).

Fenstergröße und -position

Beim allerersten Start öffnet sich das Fenster maximiert. Danach öffnet es sich wieder mit der Größe, der Position und dem maximierten/wiederhergestellten Zustand, den es beim letzten Schließen hatte.

Links und Dateien

Links auf externe Seiten (die Einträge Doc: … im Datenbankbaum, die Links der Willkommensseite, das Menü Hilfe) öffnen sich in Ihrem Standard-Webbrowser. Exporte und Als DBML exportieren öffnen den nativen Dialog Speichern unter, sodass Sie direkt wählen, wohin die Datei geschrieben wird — siehe SQL-Abfragen schreiben.

macOS: Sandbox, frühere Daten und .pgpass

Die macOS-App läuft in der App Sandbox, die ihr einen eigenen, privaten Home-Ordner gibt. Das hat zwei Folgen:

  • Daten einer früheren, nicht sandboxed Installation in ~/.omnidb sind nicht automatisch sichtbar. Beim ersten Start ohne vorhandene Daten bietet OmniDB an, sie zu importieren — wählen Sie Import… und dann Ihren bisherigen Ordner .omnidb, oder Not Now (dieser Dialog ist derzeit nur auf Englisch verfügbar). Dasselbe können Sie später über OmniDB > Daten aus vorheriger Installation importieren… nachholen.
  • ~/.pgpass ist erst lesbar, wenn Sie den Zugriff erlauben. Hat eine PostgreSQL-Verbindung kein gespeichertes Passwort, bietet die Passwortabfrage Zugriff auf .pgpass gewähren… an: Wählen Sie Ihre Datei .pgpass einmal aus (versteckte Dateien werden in diesem Dialog angezeigt), und OmniDB merkt sich die Berechtigung, sodass jede spätere PostgreSQL-Verbindung ihr Passwort dort nachschlägt — genau wie psql. Verbindungen aus .pgpass importieren… im Bereich Verbindungen gewährt denselben Zugriff. Siehe Benutzer und Verbindungen erstellen.
