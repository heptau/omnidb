Verbundene Benutzer

Der Bereich Verbundene Benutzer zeigt, wer gerade mit einem Datenbankserver verbunden ist — PostgreSQL-Backends, MySQL/MariaDB-Threads, Oracle- und SQL-Server-Sitzungen, Firebird-Attachments —, was jede dieser Verbindungen gerade tut, und ermöglicht es, eine davon zu beenden. Er ersetzt die älteren engine-spezifischen Einträge Backends/Prozessliste/Sitzungen im Kontextmenü des Datenbankbaums.

Unterstützt werden PostgreSQL, MySQL, MariaDB, Oracle, SQL Server und Firebird. SQLite kennt dieses Konzept nicht und zeigt Die Anzeige verbundener Benutzer wird für …-Verbindungen nicht unterstützt.

Den Bereich öffnen

Klicken Sie in der linken Leiste auf das Symbol Verbundene Benutzer. Wie Überwachung, Benachrichtigungen und Berechtigungen arbeitet er mit einer Verbindung, die bereits im Bereich Datenbank geöffnet ist: Oben wird die Leiste der geöffneten Verbindungs-Tabs angezeigt, und die Liste gehört zum ausgewählten Tab. Ist keine Verbindung geöffnet, zeigt er Keine Verbindung geöffnet.

Die Liste wird geladen, wenn Sie den Bereich betreten und wann immer Sie zu einem anderen Verbindungs-Tab wechseln; von selbst aktualisiert sie sich nicht. Zum Neuladen klicken Sie mit der rechten Maustaste in das Raster und wählen Aktualisieren. Die Anzahl der Zeilen wird über dem Raster angezeigt (Anzahl der Datensätze: …).

Spalten

Die Spalten sind kompakt gruppiert (zum Beispiel eine ID unter einem Namen oder Adresse und Port in einer Zeile); wenn Sie mit der Maus über eine Spaltenüberschrift fahren, wird erklärt, was sie zeigt und aus welcher Katalogspalte sie stammt.

  • PostgreSQL (pg_stat_activity): PID, Datenbank, Benutzer, Client, Anwendung, Prozessstart / Transaktionsstart, Abfragestart / Letzte Statusänderung, Wartet auf, Status, Transaktions-ID, Abfrage-ID, Prozesstyp.
  • MySQL/MariaDB (Prozessliste): Benutzer (mit der Verbindungs-ID), Host, Datenbank, Befehl, Zeit (s), Status.
  • Oracle (v$session): SID (mit Serial#), Benutzer, Status, Schema, Client, Programm, Modul / Aktion, Client-Info, Anmeldezeit, Leerlauf (s), SQL-ID, Wartet auf, Blockierende SID.
  • SQL Server (Benutzersitzungen): Sitzungs-ID, Anmeldename, Host, Programm, Status.
  • Firebird (mon$attachments, ohne das eigene Attachment von OmniDB): Verbindungs-ID, Benutzer, Remote-Adresse, Status.

Bei PostgreSQL und Oracle sind Hintergrund-/Systemprozesse standardmäßig ausgeblendet; kreuzen Sie Systemprozesse anzeigen über dem Raster an, um sie einzublenden (das Kontrollkästchen erscheint nur, wenn es solche Zeilen gibt).

Die Abfrage einer Sitzung ansehen

Bei PostgreSQL, MySQL und MariaDB öffnet ein Klick auf eine Zeile unter dem Raster einen Bereich Abfragetext mit der Anweisung, die diese Sitzung gerade ausführt (oder zuletzt ausgeführt hat), mit Syntaxhervorhebung und schreibgeschützt. Von dort können Sie sie kopieren oder mit In neuem Abfragetab öffnen in einem regulären Abfrage-Tab weiter bearbeiten, zum Beispiel um Explain darauf auszuführen.

Eine Sitzung beenden

Klicken Sie mit der rechten Maustaste auf eine Zeile und wählen Sie Beenden. Nach Ihrer Bestätigung beendet OmniDB diese Sitzung auf die Art der jeweiligen Engine — pg_terminate_backend() bei PostgreSQL, KILL bei MySQL/MariaDB und SQL Server, ALTER SYSTEM KILL SESSION … IMMEDIATE bei Oracle, Löschen der Zeile aus mon$attachments bei Firebird — und lädt die Liste neu. Dafür ist die entsprechende Berechtigung auf dem Datenbankserver nötig. Dasselbe Kontextmenü bietet außerdem Kopieren und Inhalt anzeigen für die angeklickte Zelle.
