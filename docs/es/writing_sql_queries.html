Escritura de consultas SQL

El tipo de pestaña interna más común es la Query Tab, que contiene los siguientes elementos:

  • 1) Tab Header (Cabecera de la pestaña): puede ver el nombre de la pestaña y un icono para cerrarla. Si hay una consulta en ejecución en la pestaña, verá un indicador. Si la pestaña termina de ejecutarse y está trabajando en otra pestaña, se mostrará un indicador verde. Haciendo doble clic en el nombre de la pestaña, podrá renombrarla.
  • 2) Add Tab (Añadir pestaña): puede añadir rápidamente otra pestaña interna haciendo clic en el icono de más.
  • 3) SQL Editor (Editor SQL): editor SQL completo con resaltado de sintaxis SQL, Buscar y reemplazar (Ctrl-F y Ctrl-H) y un componente de autocompletado, explicado más abajo. Consulte Atajos de teclado del editor para la lista completa de atajos del editor (selección, multicursor, navegación, plegado, etc.).
  • 4) Execute (Ejecutar): el texto contenido en el editor SQL se ejecutará contra la base de datos activa actual al hacer clic en este botón (o pulsar el atajo, Alt-Q por defecto). Si hay algún texto seleccionado en el editor SQL, se ejecutará solo el texto seleccionado. Una vez que el comando esté ejecutándose, se mostrará un botón rojo Cancel (Cancelar), que permite cancelar la ejecución (o usando el atajo, Alt-C por defecto).
  • 5) Indent SQL (Sangrar SQL): este botón dará formato a cualquier código SQL escrito en el editor SQL (atajo Alt-S por defecto, Ctrl-S en macOS).
  • 6) Query History (Historial de consultas): todos los comandos ejecutados contra la base de datos actual se almacenan en el historial de consultas, al que se puede acceder haciendo clic en este botón. También podrá filtrar por fecha y texto para encontrar el comando SQL que necesite.
  • 7) Explain (solo PostgreSQL): ejecuta su consulta SQL contra PostgreSQL anteponiendo EXPLAIN. Los resultados se mostrarán en forma textual y gráfica en la pestaña Explain (consulte Visualización de planes de consulta para más detalles).
  • 8) Explain Analyze (solo PostgreSQL): igual que el botón Explain, pero ejecuta la consulta SQL con EXPLAIN ANALYZE, lo que ejecutará realmente la consulta.
  • 9) Autocommit (solo PostgreSQL): cuando está activado, toda consulta ejecutada se confirma (commit) en la base de datos. Cuando está desactivado, OmniDB inicia una transacción y, al ejecutar una consulta, la interfaz mostrará botones que permiten al usuario hacer Commit o Rollback. El usuario también puede mantener la transacción abierta y ejecutar otros comandos.
  • 10) Backend Status (solo PostgreSQL): cuando abre una nueva pestaña de consulta, el estado es «Not Connected», porque OmniDB aún no ha iniciado un backend de PostgreSQL. Al ejecutar la primera consulta, OmniDB inicia un nuevo backend y lo mantiene vinculado a la pestaña de consulta (cada pestaña de consulta tendrá asignado su propio backend). El estado del backend (idle, active, idle in transaction, etc.) se mostrará en este campo. Al cerrar la pestaña de consulta, OmniDB finaliza el backend.
  • 11) Export File Type (Tipo de archivo de exportación): puede ser CSV, TSV, XLSX, JSON, XML o Markdown.
  • 12) Export To File (Exportar a archivo): al hacer clic en este botón, OmniDB ejecuta la consulta actual y exporta los resultados a un archivo. En la aplicación de escritorio, se abre un diálogo nativo «Save As» (Guardar como) para que pueda elegir directamente dónde guardarlo. Cuando se ejecuta como OmniDB Server basado en navegador, en cambio, el archivo se escribe primero en la carpeta temporal del servidor, y la interfaz muestra entonces un enlace para poder descargarlo a través del navegador.
  • 13) Data Results (Resultados de datos): si la consulta es un SELECT, se mostrará una cuadrícula con los resultados. Si la consulta es una DML o DDL, se mostrará el mensaje devuelto por el SGBDR.
  • 14) Messages (solo PostgreSQL): aquí se mostrará cualquier mensaje (como los generados por el comando RAISE NOTICE).
  • 15) Explain View (solo PostgreSQL): muestra un componente completo para ver el plan de ejecución de PostgreSQL en forma textual o gráfica.

Una vez ejecutadas, las pestañas también se guardan en la base de datos de usuario de OmniDB (título y contenido), por lo que la próxima vez que abra OmniDB las verá todas abiertas de nuevo. Además, cada comando que ejecute en una pestaña de consulta se guarda en su historial de consultas y también en el archivo omnidb.log.

Autocompletado SQL

El editor SQL tiene una función que ayuda mucho al crear nuevas consultas: el autocompletado de código SQL. Con esta función es posible autocompletar columnas contenidas en una tabla referenciada mediante un alias.
