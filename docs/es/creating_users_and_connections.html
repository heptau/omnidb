Creación de usuarios y conexiones

Inicio de sesión como el usuario admin

OmniDB viene únicamente con el usuario admin. Si está usando la versión de servidor, lo primero que debe hacer es iniciar sesión como admin; la contraseña predeterminada es admin. No necesita iniciar sesión en la versión de aplicación.

La siguiente ventana es la ventana inicial.

Creación de otro usuario

Haga clic en el icono Users (Usuarios) de la esquina superior derecha. Se abrirá una ventana emergente que permite al superusuario actual de OmniDB crear un nuevo usuario de OmniDB.

Haga clic en el botón Add new user (Añadir nuevo usuario) (el icono de persona con un signo más) dentro de la ventana emergente. Se inserta una nueva fila de usuario en blanco, mostrada como (pending info) hasta que la complete.

Complete el username (nombre de usuario) y la password (contraseña). Marque si desea que este nuevo usuario sea super user (superusuario). Esta ventana de administración de usuarios solo la ven los superusuarios. Cuando termine, haga clic en el botón Save (Guardar) dentro de la ventana emergente.

Puede crear tantos usuarios como desee, editar usuarios existentes y también eliminar usuarios haciendo clic en la cruz roja de la columna de acciones. Ahora puede cerrar sesión haciendo clic en el botón Sign Out (Cerrar sesión) en la esquina superior derecha.

Creación de conexiones

OmniDB admite PostgreSQL, MySQL, MariaDB, Oracle y SQLite.

Crearemos ahora una conexión a una base de datos PostgreSQL, una conexión a una base de datos Oracle y una conexión a una base de datos MariaDB. Para crear las conexiones, debe hacer clic en el botón New Connection (Nueva conexión) y luego elegir el tipo de conexión y completar los demás campos. Tras completar todos los campos de ambas conexiones, haga clic en el botón Save (Guardar).

Para cada conexión hay una columna Actions (Acciones) donde puede eliminarlas, probarlas y seleccionarlas. Adelante, pruebe la conexión de PostgreSQL.

Observe que aparece una ventana emergente con el mensaje fe_sendauth: no password supplied. Esto ocurre porque OmniDB no almacena la contraseña del usuario de la base de datos en disco. Al no disponer de ninguna contraseña, OmniDB intentará conectarse sin ella, tratando así de aprovechar los métodos de autenticación automática que puedan estar disponibles: el método trust, un archivo .pgpass, etc. Como el servidor de base de datos responde con un error que no permite conectarse al usuario, OmniDB entiende que se requiere una contraseña y la solicita al usuario. Cuando el usuario escribe una contraseña en esta ventana emergente, la contraseña se cifra y se almacena en memoria.

Después de escribir la contraseña y pulsar Enter, si la conexión con la base de datos tiene éxito, verá una ventana emergente de confirmación.

Pero, si tiene algún problema al conectarse a su base de datos PostgreSQL, la misma ventana emergente seguirá mostrando el error que obtuvo OmniDB.

Uso de túneles SSH

OmniDB permite al usuario conectarse a cualquier base de datos remota a través de túneles SSH. El usuario debe completar la información del túnel SSH en cada conexión de la Connections Grid (cuadrícula de conexiones).

  • SSH Server (Servidor SSH): el servidor al que se conecta mediante SSH;
  • SSH Port (Puerto SSH): el puerto del servidor SSH (por defecto es 22, pero puede ser cualquier número de puerto);
  • SSH User (Usuario SSH): el nombre de usuario del sistema operativo que usa para conectarse al servidor SSH;
  • Password/Passphrase (Contraseña/Frase de contraseña): la contraseña del usuario del sistema operativo (o la frase de contraseña de la clave indicada más abajo). Si completa el campo SSH Key Text File, la contraseña es opcional;
  • SSH Key Text File (Archivo de texto de clave SSH): el contenido de la clave SSH privada local que puede usar para conectarse a el servidor SSH. Si completa este campo, también puede completar el campo Password/Passphrase, pero en este caso será la frase de contraseña de la clave privada SSH.

Tenga en cuenta que toda la información se almacena cifrada en su User Database (base de datos de usuario) local de OmniDB.

Al usar túneles SSH, también debe completar todos los campos de la base de datos de forma acorde. Pero en lugar de ser relativos al servidor de OmniDB, serán relativos al servidor SSH. Esto puede hacerse en 2 escenarios, como se explica a continuación.
