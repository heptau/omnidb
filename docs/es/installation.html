Instalación

OmniDB ofrece 2 tipos de paquetes para adaptarse a las necesidades de cada usuario:

  • OmniDB Application: ejecuta un servidor web en un puerto aleatorio por debajo, y proporciona una ventana de navegador simplificada para usar la interfaz de OmniDB sin ninguna configuración adicional. Se siente igual que una aplicación de escritorio.
  • OmniDB Server: ejecuta un servidor web en un puerto aleatorio, o en un puerto especificado por el usuario. El usuario debe conectarse a él a través de un navegador web. Ofrece gestión de usuarios, ideal para alojarse en un servidor dentro de la red de los usuarios.

Tanto la aplicación como el servidor pueden instalarse en la misma máquina.

OmniDB Application

Importante: el repositorio original https://github.com/OmniDB/OmniDB/releases contiene solo versiones antiguas (hasta ~2020) y ya no se mantiene — consulte Funciones heredadas e historial para saber qué cambió desde entonces.

Para las versiones actuales, use la página de versiones del proyecto revivido. Desde la reescritura en Go, cada versión es un único archivo autocontenido por plataforma — sin instalador, sin runtime independiente que instalar previamente:

  • macOS (Apple Silicon o Intel): OmniDB-macOS-osx-arm64.zip / OmniDB-macOS-osx-x64.zip
  • Linux x64: OmniDB-linux-x64.tar.gz
  • Windows x64: OmniDB-win-x64.zip

Descomprima (o extraiga) el archivo correspondiente a su plataforma y ejecute la aplicación/binario OmniDB dentro — eso es toda la instalación. Las compilaciones de Linux y Windows las genera el CI en cada versión, pero aún no se han verificado en hardware real, a diferencia de la compilación de macOS; si encuentra un problema específico de alguna de esas plataformas, por favor abra un issue.

Instalación mediante Homebrew (solo macOS – recomendado)

Para los usuarios de macOS que prefieran usar un gestor de paquetes, OmniDB está disponible a través de un tap personalizado de Homebrew:

# Install the latest version:
brew install --cask heptau/tap/omnidb
# To upgrade later:
brew upgrade heptau/tap/omnidb

Homebrew descargará automáticamente el ZIP correcto para su arquitectura (Apple Silicon o Intel), lo descomprimirá y colocará OmniDB.app en su carpeta de Aplicaciones.

La definición del cask se mantiene aquí: heptau/homebrew-tap – omnidb.rb

Descarga directa (todas las plataformas)

  • macOS (Apple Silicon)
  • macOS (Intel)
  • Linux (x64)
  • Windows (x64)

Estos enlaces siempre apuntan a la última versión. Para versiones anteriores, sumas de comprobación y notas de la versión, consulte la página de versiones.

Descomprima el archivo correspondiente a su plataforma y lance la aplicación de la forma habitual: en macOS, arrastre OmniDB.app a Applications y ábrala desde Launchpad/Spotlight o con open -a OmniDB; en Linux, ejecute el binario OmniDB directamente; en Windows, ejecute OmniDB.exe.

OmniDB Server

El mismo archivo de la versión también contiene omnidb-server — un binario independiente, sin interfaz gráfica, junto a la aplicación de escritorio (la aplicación de escritorio en realidad lanza este mismo binario internamente, como proceso hijo, forzando el modo aplicación). Ejecútelo directamente para el modo servidor accesible por navegador, sin ningún shell de escritorio de por medio:

user@machine:~$ ./omnidb-server
omnidb-server: listening on 127.0.0.1:52149 — open http://127.0.0.1:52149/omnidb_login/ in your browser

Por defecto, OmniDB escucha únicamente en 127.0.0.1 y elige un puerto libre automáticamente. Puede especificar ambos explícitamente:

user@machine:~$ ./omnidb-server -p 8080 -H 0.0.0.0
omnidb-server: listening on 0.0.0.0:8080 — open http://0.0.0.0:8080/omnidb_login/ in your browser

Consulte Despliegue de omnidb-server para el conjunto completo de opciones y las configuraciones de despliegue recomendadas (en particular, por qué se desaconseja exponer -H 0.0.0.0 directamente a internet sin un proxy inverso delante — no hay soporte TLS integrado).

OmniDB con Oracle

Ni la aplicación ni el servidor de OmniDB requieren software adicional para conectarse a Oracle — a diferencia de versiones anteriores, no se necesita instalar un Oracle Instant Client independiente. La conectividad con Oracle está implementada de forma nativa (un driver puro en Go), por lo que funciona de fábrica igual que cualquier otra base de datos compatible.

Base de datos de usuario de OmniDB

En la primera ejecución, tanto el servidor como la aplicación crean un archivo ~/.omnidb/omnidb-app/omnidb.db (para OmniDB app) o ~/.omnidb/omnidb-server/omnidb.db (para OmniDB server) en el directorio home del usuario, si aún no existe — junto con una cuenta de superusuario admin/admin predeterminada, lista para iniciar sesión de inmediato. Este archivo también se llama la base de datos de usuario y contiene todos los usuarios, conexiones y demás datos de la aplicación. Si ya existe (por ejemplo, tras una actualización), OmniDB lo usa tal cual — nunca se sobrescribe ni se restablece automáticamente.
