Replicación lógica

PostgreSQL 10 introduce la replicación lógica nativa, que usa un modelo de publicación/suscripción, por lo que podemos crear publicaciones en el origen (o publicador) y suscripciones en el destino (o suscriptor). Para más detalles al respecto, consulte la documentación de PostgreSQL documentación.

En este capítulo, usaremos un clúster de 2 nodos para demostrar la replicación lógica nativa de PostgreSQL 10. Tenga en cuenta que en cada instancia de PostgreSQL necesita configurar wal_level = logical y también asegurarse de ajustar el archivo pg_hba.conf para conceder acceso a replication entre los 2 nodos.

Creación de un entorno de prueba

Configure dos instancias de PostgreSQL 10+ como prefiera (Docker, una máquina virtual, o incluso dos bases de datos en la misma máquina) y configure los ajustes anteriores en cada una.

Conexión a ambos nodos

Luego seleccione ambas conexiones. Observe cómo OmniDB entiende que está conectado a PostgreSQL 10 y habilita un nuevo nodo en la vista de árbol de la conexión actual: se llama Logical Replication (Replicación lógica). Dentro de él, podemos ver Publications (Publicaciones) y Subscriptions (Suscripciones).

Creación de una tabla de prueba en ambos nodos

En ambos nodos, cree una tabla como esta:

CREATE TABLE customers (
 login text PRIMARY KEY,
 full_name text NOT NULL,
 registration_date timestamptz NOT NULL DEFAULT now()
)
