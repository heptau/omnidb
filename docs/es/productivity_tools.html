Herramientas de productividad

OmniDB incluye varias herramientas que ahorran clics y pulsaciones de teclas. Funcionan con todas las bases de datos compatibles, salvo que se indique lo contrario, y todo lo que modificaría una base de datos (un cambio de nombre, una sincronización de esquema, una restauración) se muestra primero como SQL: lo ejecuta usted mismo.

Encontrar cosas

Buscar en todas partes. Pulse Shift dos veces para abrir la paleta. En un solo cuadro encuentra secciones, conexiones, marcadores, snippets y, para la conexión seleccionada, tablas (a partir de dos caracteres escritos), sin distinguir mayúsculas ni acentos. Las flechas se mueven por la lista, Enter abre la selección (una tabla se abre en Edit Data) y Esc la cierra.

Marcadores. Haga clic con el botón derecho en una tabla del árbol y elija Añadir a marcadores. La sección Marcadores de la barra izquierda lista las tablas fijadas por conexión; al hacer clic en una se abre la conexión (si aún no lo está) y la tabla en Edit Data, y la cruz la quita. Los marcadores son privados para cada usuario de OmniDB.

La barra izquierda y las conexiones

Panel de navegación. En Ajustes > Panel de navegación elige qué elementos muestra la barra de la izquierda, los ordena con las flechas y mueve el separador entre su parte superior e inferior. El icono de Ajustes es siempre el último y no se puede ocultar. Cada cambio surte efecto al instante, sin recargar, y se guarda para su usuario.

Conexión de solo lectura. Márquela en el formulario de conexión y se rechazan las escrituras a través de esa conexión; la lista de conexiones, la pestaña de base de datos y el menú de la conexión muestran un candado. PostgreSQL, MySQL/MariaDB y SQLite además ponen la propia sesión en solo lectura, y en todos los motores el editor de consultas, la consola y Edit Data rechazan todo lo que no sean sentencias de tipo SELECT. Es una red de seguridad contra accidentes (la pestaña de producción olvidada abierta), no un límite de seguridad: para una garantía firme use un rol de base de datos sin privilegios de escritura.

El editor SQL

  • Autocompletado según el contexto. Se analiza la sentencia que se edita para saber en qué cláusula está el cursor y de qué tablas, subconsultas y CTE lee. alias., tabla. y cte. listan las columnas de esa referencia; una palabra suelta en SELECT, WHERE, GROUP BY, ORDER BY, HAVING, SET, RETURNING o en la lista de columnas de un INSERT ofrece las columnas de las tablas de la sentencia; tras ON encabezan la lista las condiciones de clave foránea entre la tabla que se une y las anteriores; tras FROM, JOIN, UPDATE o INTO vienen los nombres de CTE de la sentencia y las tablas de la conexión.
  • Inspecciones en vivo. Tras una pausa al escribir, los problemas se marcan en el margen (al pasar el ratón aparece el mensaje) y con un subrayado punteado: UPDATE o DELETE sin WHERE, comparaciones con NULL mediante = o <>, un JOIN sin ON ni USING, un alias al que nada hace referencia y una tabla o vista que la base de datos no conoce.
  • Ir a la definición y Buscar usos. Ctrl/Cmd+clic (o Ctrl/Cmd+B) sobre un nombre: un alias o CTE salta a su definición, una tabla o vista abre su DDL en una pestaña nueva. Alt+F7 selecciona todas las menciones de un alias o CTE en la sentencia y, para una tabla, lista dónde aparece (en el editor, en sus snippets y en el historial de consultas); cada entrada se puede pulsar.
  • Renombrar… (Shift+F6 o el menú contextual del editor). Un alias o CTE se renombra en toda la sentencia a la vez. Una tabla o columna abre una vista previa: la sentencia ALTER/RENAME para su base de datos se escribe en una pestaña nueva para que la ejecute usted, junto con las líneas de sus snippets que mencionan el nombre antiguo (cada una con una casilla) y las menciones en el editor actual. Solo se reescribe código, nunca cadenas ni comentarios.
  • Plantillas en vivo. Escriba una abreviatura y pulse Tab para expandirla en el esqueleto de una sentencia; luego Tab / Shift+Tab recorren sus marcadores. Incluidas: sel, cnt, grp, ins, upd, del, jn, cte, crt. Las suyas viven en la sección Snippets como snippets dentro de una carpeta llamada Live templates: el nombre del snippet es la abreviatura y su texto la plantilla (${1:valor} para un marcador, $0 para la posición final del cursor).
  • Parámetros con nombre. Una sentencia con marcadores :nombre pide un valor por parámetro antes de ejecutarse. Cada valor se deduce (números, NULL y TRUE/FALSE quedan tal cual, cualquier otra cosa se convierte en una cadena entrecomillada), se fuerza a texto o se pega como SQL sin procesar. Los marcadores dentro de cadenas, comentarios, ::conversiones y rebanadas de matrices se dejan en paz.
  • Historial local. Lo que escribe se guarda como versión (tras una pausa al escribir y cuando el editor pierde el foco), hasta 100 por conexión y usuario. El botón de historial de la barra de herramientas de consultas las lista y muestra las líneas que desaparecerían y volverían si restaurase la versión elegida; Restaurar la pone en el editor, guardando antes el texto que reemplaza.
  • Plegado y multicursor. Las sentencias de varias líneas tienen un control de plegado en el margen; Alt+J selecciona la siguiente aparición de la palabra bajo el cursor (Alt+Shift+J la anterior) para editar varios sitios a la vez.
  • Generar (menú contextual de una tabla). SELECT con JOIN (claves foráneas) escribe un SELECT de las columnas de la tabla más las de cada tabla a la que apuntan sus claves foráneas, cada una como LEFT JOIN; Script CRUD escribe INSERT / SELECT / UPDATE / DELETE para una fila direccionada por la clave primaria, con parámetros :con_nombre. Ambos se abren en una pestaña de consulta nueva.

Resultados de consultas

  • Filtro. El cuadro junto al botón de exportación reduce la cuadrícula a las filas que contienen todas las palabras escritas (en cualquier celda, sin distinguir mayúsculas; null coincide con celdas NULL) y muestra «N de M». Solo mira las filas ya obtenidas.
  • Acciones de fila (clic derecho en una celda): Vista de registro muestra la fila como una tabla vertical columna / valor; Copiar fila como INSERT, Copiar fila como JSON, Copiar fila como Markdown y Copiar fila como CSV la copian en ese formato; Estadísticas de la columna cuenta valores no vacíos, NULL y distintos y, en los numéricos, suma, promedia y acota las filas cargadas.
  • Visor del contenido de una celda. Al abrir el contenido de una celda se ofrecen Format JSON y Minify JSON mientras el texto sea JSON válido (números y cadenas se conservan carácter por carácter), un interruptor Wrap lines y un botón Copy.
  • Gráfico del resultado. El botón de gráfico de la barra de herramientas de consultas dibuja las filas que muestra la cuadrícula como gráfico de barras, líneas, circular o de anillo: elija la columna del eje x y marque las columnas numéricas que dibujar (hasta las primeras 500 filas).
  • Exportación SQL. Entre los formatos de exportación está SQL, que escribe sentencias INSERT INTO … VALUES …;, una por fila, con el entrecomillado de la base de datos de la conexión.

Edit Data e importación

  • Duplicar fila copia una fila en un nuevo INSERT pendiente (las columnas de la clave primaria quedan vacías para que la base de datos las genere).
  • Ir a la fila referenciada (clic derecho en una celda de clave foránea) abre la tabla referenciada en Edit Data, ya filtrada a la fila a la que apunta el valor; se admiten claves compuestas.
  • Importar datos… (clic derecho en una tabla) carga un archivo CSV, TSV o JSON (una matriz de objetos o de matrices). El delimitador se detecta o se elige, las columnas del archivo se asignan a las de la tabla con una vista previa de las primeras filas, y los valores vacíos pueden convertirse en NULL. Las filas se insertan en una sola transacción, de modo que una fila errónea (nombrada en el error) deja la tabla intacta; hasta 200 000 filas a la vez y nunca en una conexión de solo lectura.

Volcado, restauración y ejecución de archivos de script

Volcar tabla (estructura y datos) a un archivo SQL y Volcar tabla (solo estructura) a un archivo SQL (menú Generar de una tabla) escriben el DDL de la tabla, seguido de un INSERT por fila, en un archivo SQL; no hace falta ningún programa externo. El botón Ejecutar un script SQL desde un archivo (restaurar un volcado) de la barra de herramientas de consultas ejecuta ese archivo (o cualquier script SQL) sentencia a sentencia en una transacción, de modo que una sentencia que falla (nombrada en el error) deshace el resto allí donde la base de datos tenga DDL transaccional. Hasta 48 MB y 1 000 000 de sentencias; se rechaza en una conexión de solo lectura.

Comparar

El botón de las flechas de la barra de herramientas de consultas compara la conexión actual con otra: o bien el esquema (tablas, columnas y sus tipos), o bien las filas de una tabla por clave primaria. El resultado es un resumen más un script que deja el destino igual que el origen (CREATE TABLE, ADD COLUMN, cambios de tipo, INSERT/UPDATE de filas), abierto en una pestaña de la conexión de destino para que lo lea y lo ejecute: comparar no cambia nada. Las sentencias destructivas (DROP, DELETE de filas) solo se escriben como comentarios salvo que pida los borrados. No se comparan la nulabilidad, los valores por defecto, los índices ni las restricciones.

Consultas programadas

La sección Consultas programadas de la barra izquierda ejecuta SQL en una conexión cada N minutos (de 1 minuto a una semana). Las programaciones aparecen a la izquierda, en una lista con pie + / −; los ajustes de la seleccionada (nombre, intervalo, SQL) a la derecha, con Ejecutar ahora, Pausar / Reanudar y sus últimas 50 ejecuciones (estado, duración y qué hizo cada sentencia, o el error en el que se detuvo). El botón del calendario de la barra de herramientas de consultas guarda el SQL del editor (la selección, o si no todo el texto) como una programación nueva. El planificador vive en el proceso servidor de OmniDB, así que solo funciona mientras OmniDB está abierto; una ejecución que venció con la aplicación cerrada ocurre una vez en el siguiente inicio. Las conexiones de solo lectura siguen rechazando escrituras, y las conexiones con túnel SSH o autenticación por token no se pueden programar.

Control de versiones (git)

El botón de la rama bajo el árbol de snippets (y bajo la lista de unidades de monitorización) guarda sus definiciones compartibles en un repositorio git como archivos de texto: los snippets como archivos .sql en snippets/ (un directorio por carpeta de snippets), las unidades de monitorización propias como monitoring/<motor>/*.json y las consultas programadas como schedules/<alias de la conexión>/*.json (solo el alias y el SQL; nunca una dirección ni credenciales). Confirmar cambios (commit) escribe los archivos, elimina los .sql/.json que ya no corresponden a nada y los confirma; Importar desde la carpeta los lee de vuelta, creando o actualizando definiciones y sin borrar nunca ninguna. Una programación importada empieza en pausa para que nada se ejecute sin supervisión.

Git se ejecuta dentro de OmniDB, por lo que no hace falta tener git instalado. En la aplicación de escritorio el repositorio vive en una carpeta dentro del directorio propio de OmniDB hasta que elija otra con Elegir carpeta… (se recuerda entre arranques). En macOS esa carpeta integrada está dentro del contenedor de la aplicación, que otros programas no pueden abrir: elija su propia carpeta si quiere hacer push del repositorio con sus herramientas de git. En un servidor multiusuario se escribe la ruta de la carpeta y la función está limitada a los superusuarios. El push y el pull quedan en manos de sus propias herramientas de git.
