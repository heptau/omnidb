Outil de configuration OmniDB

Remarque : l’utilitaire en ligne de commande autonome omnidb-config/ omnidb-config-app/omnidb-config-server décrit sur cette page appartenait à l’ancienne version basée sur Python/Django et ne fait pas partie de la version actuelle. Le binaire unique omnidb-server n’accepte que -A/--app (mode application de bureau) et -d/--homedir (choisir le répertoire personnel), documentés dans le chapitre Installation. Les tâches de maintenance que proposait l’ancien outil peuvent toujours être effectuées manuellement, comme décrit ci-dessous.

Répertoire personnel

OmniDB stocke tout — la base de données omnidb.db (utilisateurs, connexions et autres données de l’application) et un dossier temp pour les fichiers exportés — dans un unique répertoire personnel. Par défaut, il s’agit de ~/.omnidb/omnidb-app (mode bureau) ou ~/.omnidb/omnidb-server (mode serveur) ; indiquez -../chemin pour en utiliser un autre.

Créer un utilisateur

Il n’existe actuellement aucune option en ligne de commande pour créer un utilisateur sans ouvrir OmniDB. Lors de la première exécution sur un répertoire personnel vide, OmniDB crée automatiquement un superutilisateur par défaut admin/admin — connectez-vous avec celui-ci et créez d’autres utilisateurs depuis l’écran Users (Utilisateurs), ou changez le mot de passe par défaut.

Purge (Vacuum)

OmniDB possède une seule base de données SQLite, omnidb.db, qui stocke tous les utilisateurs, connexions et autres données liées à OmniDB. Comme il s’agit d’un simple fichier SQLite, vous pouvez le purger avec n’importe quel client SQLite pendant qu’OmniDB n’est pas en cours d’exécution, par exemple :

user@machine:~$ sqlite3 ~/.omnidb/omnidb-app/omnidb.db 'VACUUM;'

Réinitialiser la base de données

Si vous souhaitez effacer toutes les informations d’OmniDB et obtenir une base de données propre, comme si elle venait d’être installée, quittez OmniDB et supprimez (ou déplacez ailleurs) le fichier omnidb.db du répertoire personnel. Un nouveau fichier vide — avec un nouvel utilisateur par défaut admin/admin — est créé automatiquement au prochain démarrage d’OmniDB. Utilisez cette opération avec prudence : elle est irréversible.

Supprimer les fichiers temporaires

Les résultats de requêtes exportés (CSV/XLSX/etc.) sont écrits dans le dossier temp du répertoire personnel. Il est possible de supprimer son contenu manuellement à tout moment pendant qu’OmniDB n’est pas en cours d’exécution ; OmniDB le recrée si nécessaire.
