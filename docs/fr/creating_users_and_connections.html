Créer des utilisateurs et des connexions

Connexion en tant qu’utilisateur admin

OmniDB est livré uniquement avec l’utilisateur admin. Si vous utilisez la version serveur, la première chose à faire est de vous connecter en tant qu’admin, le mot de passe par défaut étant admin. Vous n’avez pas besoin de vous connecter dans la version application.

La fenêtre suivante est la fenêtre initiale.

Création d’un autre utilisateur

Cliquez sur l’icône Users (Utilisateurs) dans le coin supérieur droit. Une fenêtre contextuelle s’ouvre, permettant au superutilisateur OmniDB actuel de créer un nouvel utilisateur OmniDB.

Cliquez sur le bouton Add new user (Ajouter un utilisateur) (l’icône de silhouette avec un plus) à l’intérieur de la fenêtre contextuelle. Une nouvelle ligne d’utilisateur vide est insérée, affichée comme (pending info) (en attente d’informations) jusqu’à ce que vous la remplissiez.

Renseignez le nom d’utilisateur et le mot de passe. Cochez la case si vous souhaitez que ce nouvel utilisateur soit un superutilisateur. Cette fenêtre de gestion des utilisateurs n’est visible que par les superutilisateurs. Une fois terminé, cliquez sur le bouton Save (Enregistrer) à l’intérieur de la fenêtre contextuelle.

Vous pouvez créer autant d’utilisateurs que vous le souhaitez, modifier les utilisateurs existants et également supprimer des utilisateurs en cliquant sur la croix rouge dans la colonne des actions. Vous pouvez maintenant vous déconnecter en cliquant sur le bouton Sign Out (Se déconnecter) dans le coin supérieur droit.

Création de connexions

OmniDB prend en charge PostgreSQL, MySQL, MariaDB, Oracle et SQLite.

Nous allons maintenant créer une connexion à une base de données PostgreSQL, une connexion à une base de données Oracle et une connexion à une base de données MariaDB. Pour créer les connexions, vous devez cliquer sur le bouton New Connection (Nouvelle connexion), puis choisir le type de connexion et renseigner les autres champs. Une fois tous les champs remplis pour les deux connexions, cliquez sur le bouton Save (Enregistrer).

Pour chaque connexion, il existe une colonne Actions permettant de la supprimer, de la tester et de la sélectionner. Testez maintenant la connexion PostgreSQL.

Remarquez qu’une fenêtre contextuelle apparaît avec le message fe_sendauth : no password supplied. Cela se produit parce qu’OmniDB ne stocke pas le mot de passe de l’utilisateur de la base de données sur le disque. Ne disposant d’aucun mot de passe, OmniDB tente de se connecter sans en fournir un, essayant ainsi de tirer parti des méthodes d’authentification automatique éventuellement en place : méthode trust, fichier .pgpass, etc. Comme le serveur de base de données répond par une erreur empêchant l’utilisateur de se connecter, OmniDB comprend alors qu’un mot de passe est requis et le demande à l’utilisateur. Lorsque l’utilisateur saisit un mot de passe dans cette fenêtre contextuelle, celui-ci est chiffré et conservé en mémoire.

Après avoir saisi le mot de passe et appuyé sur Entrée, si la connexion à la base de données réussit, une fenêtre contextuelle de confirmation s’affiche.

Mais si vous rencontrez le moindre problème de connexion à votre base de données PostgreSQL, la même fenêtre contextuelle restera affichée avec l’erreur obtenue par OmniDB.

Utilisation des tunnels SSH

OmniDB permet à l’utilisateur de se connecter à n’importe quelle base de données distante via des tunnels SSH. L’utilisateur doit renseigner les informations du tunnel SSH pour chaque connexion dans la grille des connexions (Connections Grid).

  • SSH Server : le serveur auquel vous vous connectez via SSH ;
  • SSH Port : le port du serveur SSH (par défaut 22, mais cela peut être n’importe quel numéro de port) ;
  • SSH User : le nom d’utilisateur du système d’exploitation utilisé pour vous connecter au serveur SSH ;
  • Password/Passphrase : le mot de passe de l’utilisateur du système d’exploitation (ou la phrase secrète de la clé ci-dessous). Si vous renseignez le champ SSH Key Text File, un mot de passe est facultatif ;
  • SSH Key Text File : le contenu de la clé privée SSH locale que vous pouvez utiliser pour vous connecter au serveur SSH. Si vous renseignez ce champ, vous pouvez également renseigner le champ Password/Passphrase, mais dans ce cas il s’agira de la phrase secrète de la clé privée SSH.

Veuillez noter que toutes ces informations sont stockées chiffrées dans votre base de données utilisateur OmniDB locale.

Lorsque vous utilisez des tunnels SSH, vous devez également renseigner tous les champs de la base de données en conséquence. Mais au lieu d’être relatifs au serveur OmniDB, ils seront relatifs au serveur SSH. Cela peut se faire selon 2 scénarios expliqués ci-dessous.
