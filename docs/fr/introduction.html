Introduction

OmniDB est une application open source accessible depuis un navigateur, conçue pour accéder à de nombreux systèmes de gestion de bases de données et les administrer, par exemple PostgreSQL, Oracle et MySQL. OmniDB peut fonctionner soit comme une application de bureau, soit via un navigateur, combinant la flexibilité nécessaire pour les différents modes d'accès avec une conception qui place la sécurité au premier plan. OmniDB est développée activement, testée automatiquement sur diverses bases de données et divers navigateurs, et fournie avec une documentation complète.

Dès les premières phases de son développement, OmniDB a été conçue comme une application accessible depuis un navigateur. Elle fonctionne donc dans n'importe quel navigateur, sur n'importe quel système d'exploitation. Elle peut être utilisée depuis plusieurs ordinateurs et par plusieurs utilisateurs, chacun disposant de son propre groupe de connexions. Elle peut également être hébergée sur n'importe quel système d'exploitation, sans qu'il soit nécessaire d'installer la moindre dépendance. Nous verrons plus en détail l'installation dans les chapitres suivants.

L'objectif principal d'OmniDB est d'offrir un espace de travail unifié regroupant toutes les fonctionnalités nécessaires pour manipuler différents SGBD. Aucun outil spécifique à un SGBD n'est requis : dans OmniDB, le changement de contexte entre différents SGBD se fait par un simple changement de connexion, sans quitter la page en cours. L'utilisateur final a l'impression qu'il n'y a aucune différence lorsqu'il manipule différents SGBD : cela ressemble simplement à des connexions différentes.

Malgré cela, OmniDB est conçue avec un souci de simplicité, pensée pour être une application rapide et légère accessible depuis un navigateur. Les traitements de longue durée — requêtes, procédures et supervision — s'exécutent en arrière-plan et sont retransmis au navigateur au fur et à mesure de leur achèvement, ce qui permet à l'utilisateur de continuer à travailler sur plusieurs bases de données et plusieurs serveurs en même temps, sans être bloqué par l'un d'entre eux.

OmniDB est également sécurisée. Toutes les données utilisateur d'OmniDB sont stockées chiffrées, et aucun mot de passe de base de données n'est jamais stocké. Lorsque l'utilisateur se connecte pour la première fois à une base de données, OmniDB demande le mot de passe. Ce mot de passe est chiffré et conservé en mémoire pendant une durée déterminée. Une fois ce délai écoulé, OmniDB redemande le mot de passe. Cela garantit une sécurité maximale pour la base de données à laquelle OmniDB se connecte.

Historique

Les créateurs d'OmniDB, Rafael Thofehrn Castro et William Ivanski, travaillaient dans une entreprise où ils devaient gérer quotidiennement plusieurs bases de données différentes appartenant à des clients. Ces bases de données provenaient de technologies de SGBD différentes, et ils devaient donc constamment basculer entre outils de gestion de bases de données (généralement un par SGBD). N'étant pas satisfaits des outils de gestion unifiée de bases de données existants (capables de gérer différents SGBD), ils ont eu l'idée principale d'OmniDB.

La première version d'OmniDB a été présentée comme projet de fin d'études de licence en informatique à l'Université fédérale du Paraná, au Brésil. L'objectif était de tracer une ligne commune entre les SGBD populaires et d'étudier en profondeur leurs métadonnées. Le résultat fut un outil écrit en ASP.NET/C#, capable de se connecter et d'identifier les principales structures (tables, clés, index et contraintes) de manière générique, pour plusieurs SGBD :

  • Firebird
  • MariaDB / MySQL
  • Oracle
  • PostgreSQL
  • SQLite
  • Microsoft SQL Server

La première version d'OmniDB permettait également la conversion entre tous les SGBD pris en charge par l'outil. Cette fonctionnalité a été conçue pour être conviviale, ne nécessitant que quelques étapes : l'utilisateur doit sélectionner une connexion source, les structures qui seront converties (uniquement les tables et toutes leurs structures, avec leurs données) et la connexion cible.

En 2025-2026, le projet a été relancé avec des versions majeures (3.1.x), axées sur la modernisation de la base de code, l'amélioration de la sécurité et l'ajout d'une prise en charge complète des systèmes d'exploitation modernes comme macOS Silicon, accompagnées d'une refonte complète de la documentation. Cette relance a culminé avec une réécriture complète du backend, passant de Python/Django à Go (3.6.x), supprimant entièrement l'environnement d'exécution Python et livrant un binaire natif unique pour chaque plateforme. Consultez Anciennes fonctionnalités et historique pour la chronologie complète des versions et le détail des changements survenus au fil du temps.
