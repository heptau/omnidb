Utilisateurs connectés

La section Utilisateurs connectés montre qui est connecté à un serveur de base de données en ce moment — processus serveur PostgreSQL, threads MySQL/MariaDB, sessions Oracle et SQL Server, connexions (attachments) Firebird — ce que fait chacun d’eux, et vous permet d’en terminer un. Elle remplace les anciennes entrées propres à chaque moteur Processus serveur/Liste des processus/Sessions du menu contextuel de l’arborescence de la base de données.

Moteurs pris en charge : PostgreSQL, MySQL, MariaDB, Oracle, SQL Server et Firebird. SQLite n’a pas de notion équivalente et affiche L’affichage des utilisateurs connectés n’est pas pris en charge pour les connexions ….

Ouvrir la section

Cliquez sur l’icône Utilisateurs connectés dans la barre de navigation de gauche. Comme Supervision, Notifications et Autorisations, elle fonctionne sur une connexion déjà ouverte dans la section Base de données : la bande des onglets de connexion ouverts est affichée en haut, et la liste correspond à l’onglet sélectionné. Si aucune connexion n’est ouverte, elle affiche Aucune connexion ouverte.

La liste est chargée lorsque vous entrez dans la section et chaque fois que vous passez à un autre onglet de connexion ; elle ne s’actualise pas d’elle-même. Pour la recharger, faites un clic droit sur la grille et choisissez Actualiser. Le nombre de lignes est affiché au-dessus de la grille (Nombre d’enregistrements : …).

Colonnes

Les colonnes sont regroupées de façon compacte (par exemple un ID sous un nom, ou l’adresse et le port sur une même ligne) ; survoler un en-tête de colonne explique ce qu’elle affiche et de quelle colonne du catalogue elle provient.

  • PostgreSQL (pg_stat_activity) : PID, Base de données, Utilisateur, Client, Application, Démarrage du processus / Démarrage de la transaction, Démarrage de la requête / Dernier changement d’état, En attente de, État, ID de transaction, ID de requête, Type de processus.
  • MySQL/MariaDB (liste des processus) : Utilisateur (avec l’ID de connexion), Hôte, Base de données, Commande, Temps (s), État.
  • Oracle (v$session) : SID (avec le Serial#), Utilisateur, État, Schéma, Client, Programme, Module / action, Infos client, Heure de connexion, Inactif (s), ID SQL, En attente de, SID bloquant.
  • SQL Server (sessions utilisateur) : ID de session, Nom de connexion, Hôte, Programme, État.
  • Firebird (mon$attachments, sans la connexion propre d’OmniDB) : ID de connexion, Utilisateur, Adresse distante, État.

Pour PostgreSQL et Oracle, les processus d’arrière-plan/système sont masqués par défaut ; cochez Afficher les processus système au-dessus de la grille pour les inclure (la case n’apparaît que lorsqu’il existe de telles lignes).

Afficher la requête d’une session

Pour PostgreSQL, MySQL et MariaDB, un clic sur une ligne ouvre sous la grille un volet Texte de la requête contenant l’instruction que cette session exécute (ou a exécutée en dernier), avec coloration syntaxique et en lecture seule. De là, vous pouvez la copier, ou utiliser Ouvrir dans un nouvel onglet de requête pour continuer à la travailler dans un onglet Requête ordinaire, par exemple pour lancer Explain dessus.

Terminer une session

Faites un clic droit sur une ligne et choisissez Terminer. Après confirmation, OmniDB met fin à cette session selon la méthode propre au moteur — pg_terminate_backend() sur PostgreSQL, KILL sur MySQL/MariaDB et SQL Server, ALTER SYSTEM KILL SESSION … IMMEDIATE sur Oracle, suppression de la ligne dans mon$attachments sur Firebird — puis recharge la liste. Cela nécessite le privilège correspondant sur le serveur de base de données. Le même menu contextuel propose également Copier et Voir le contenu pour la cellule cliquée.
