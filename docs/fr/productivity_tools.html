Outils de productivité

OmniDB propose plusieurs outils qui économisent des clics et des frappes. Ils fonctionnent avec toutes les bases de données prises en charge, sauf mention contraire, et tout ce qui modifierait une base de données (un renommage, une synchronisation de schéma, une restauration) vous est d'abord montré sous forme de SQL : c'est vous qui l'exécutez.

Retrouver les choses

Rechercher partout. Appuyez deux fois sur Shift pour ouvrir la palette. Dans un seul champ, elle trouve des sections, des connexions, des favoris, des extraits et, pour la connexion sélectionnée, des tables (à partir de deux caractères saisis), sans tenir compte de la casse ni des accents. Les flèches déplacent la sélection, Entrée ouvre le résultat (une table s'ouvre dans Edit Data) et Échap ferme la palette.

Favoris. Faites un clic droit sur une table de l'arborescence et choisissez Ajouter aux favoris. La section Favoris de la barre de gauche liste les tables épinglées par connexion ; un clic ouvre la connexion (si elle ne l'est pas encore) et la table dans Edit Data, et la croix retire le favori. Les favoris sont privés pour chaque utilisateur d'OmniDB.

La barre de gauche et les connexions

Panneau de navigation. Sous Paramètres > Panneau de navigation, vous choisissez les éléments que la barre de gauche affiche, les classez avec les flèches et déplacez le séparateur entre sa partie haute et sa partie basse. L'icône Paramètres reste toujours en dernier et ne peut pas être masquée. Chaque changement prend effet immédiatement, sans rechargement, et est enregistré pour votre utilisateur.

Connexion en lecture seule. Cochez-la dans le formulaire de connexion et les écritures passant par cette connexion sont refusées ; la liste des connexions, l'onglet de base de données et le menu de la connexion affichent un cadenas. PostgreSQL, MySQL/MariaDB et SQLite passent en plus la session elle-même en lecture seule, et, pour tous les moteurs, l'éditeur de requêtes, la console et Edit Data refusent tout ce qui n'est pas une instruction de type SELECT. C'est un filet de sécurité contre les accidents (l'onglet de production resté ouvert), pas une frontière de sécurité : pour une garantie ferme, utilisez un rôle de base de données sans privilège d'écriture.

L'éditeur SQL

  • Complétion selon le contexte. L'instruction en cours d'édition est analysée pour savoir dans quelle clause se trouve le curseur et dans quelles tables, sous-requêtes et CTE elle lit. alias., table. et cte. listent les colonnes de cette référence ; un mot isolé dans SELECT, WHERE, GROUP BY, ORDER BY, HAVING, SET, RETURNING ou dans la liste de colonnes d'un INSERT propose les colonnes des tables de l'instruction ; après ON, les conditions de clé étrangère entre la table jointe et les précédentes arrivent en tête ; après FROM, JOIN, UPDATE ou INTO viennent les noms de CTE de l'instruction et les tables de la connexion.
  • Inspections en direct. Après une pause de frappe, les problèmes sont signalés dans la marge (le message s'affiche au survol) et par un soulignement en pointillé : UPDATE ou DELETE sans WHERE, comparaisons avec NULL par = ou <>, un JOIN sans ON ni USING, un alias auquel rien ne renvoie, et une table ou vue que la base de données ne connaît pas.
  • Aller à la définition et Rechercher les utilisations. Ctrl/Cmd+clic (ou Ctrl/Cmd+B) sur un nom : un alias ou une CTE saute à sa définition, une table ou une vue ouvre son DDL dans un nouvel onglet. Alt+F7 sélectionne toutes les mentions d'un alias ou d'une CTE dans l'instruction et, pour une table, liste où elle apparaît (dans l'éditeur, dans vos extraits et dans l'historique des requêtes) ; chaque entrée est cliquable.
  • Renommer… (Maj+F6 ou le menu contextuel de l'éditeur). Un alias ou une CTE est renommé dans toute l'instruction d'un coup. Une table ou une colonne ouvre un aperçu : l'instruction ALTER/RENAME pour votre base de données est écrite dans un nouvel onglet pour que vous l'exécutiez, avec les lignes de vos extraits qui mentionnent l'ancien nom (chacune avec une case à cocher) et les mentions de l'éditeur actuel. Seul le code est réécrit, jamais les chaînes ni les commentaires.
  • Modèles dynamiques. Saisissez une abréviation et appuyez sur Tab pour la développer en squelette d'instruction, puis Tab / Maj+Tab parcourent ses emplacements. Intégrés : sel, cnt, grp, ins, upd, del, jn, cte, crt. Les vôtres vivent dans la section Extraits, sous forme d'extraits dans un dossier nommé Live templates : le nom de l'extrait est l'abréviation, son texte le modèle (${1:valeur} pour un emplacement, $0 pour la position finale du curseur).
  • Paramètres nommés. Une instruction contenant des marqueurs :nom demande une valeur par paramètre avant de s'exécuter. Chaque valeur est devinée (nombres, NULL et TRUE/FALSE restent tels quels, tout le reste devient une chaîne entre guillemets), forcée en texte ou collée comme SQL brut. Les marqueurs dans les chaînes, les commentaires, les ::casts et les tranches de tableau sont laissés tranquilles.
  • Historique local. Ce que vous tapez est enregistré comme version (après une pause de frappe et quand l'éditeur perd le focus), jusqu'à 100 par connexion et utilisateur. Le bouton d'historique de la barre d'outils des requêtes les liste et montre les lignes qui disparaîtraient et reviendraient si vous restauriez la version choisie ; Restaurer la place dans l'éditeur, en enregistrant d'abord le texte qu'elle remplace.
  • Repli et multi-curseur. Les instructions multilignes reçoivent une commande de repli dans la marge ; Alt+J sélectionne l'occurrence suivante du mot sous le curseur (Alt+Maj+J la précédente) pour modifier plusieurs endroits à la fois.
  • Générer (menu contextuel d'une table). SELECT avec JOIN (clés étrangères) écrit un SELECT des colonnes de la table plus celles de chaque table vers laquelle pointent ses clés étrangères, chacune en LEFT JOIN ; Script CRUD écrit INSERT / SELECT / UPDATE / DELETE pour une ligne adressée par la clé primaire, avec des paramètres :nommés. Les deux s'ouvrent dans un nouvel onglet de requête.

Résultats de requêtes

  • Filtre. Le champ à côté du bouton d'export réduit la grille aux lignes contenant chaque mot saisi (dans n'importe quelle cellule, sans tenir compte de la casse ; null correspond aux cellules NULL) et affiche « N sur M ». Il ne regarde que les lignes déjà récupérées.
  • Actions sur une ligne (clic droit sur une cellule) : Vue de l'enregistrement montre la ligne sous forme de tableau vertical colonne / valeur ; Copier la ligne en INSERT, Copier la ligne en JSON, Copier la ligne en Markdown et Copier la ligne en CSV la copient dans ce format ; Statistiques de la colonne compte les valeurs non vides, NULL et distinctes et, pour les numériques, en donne la somme, la moyenne et les bornes sur les lignes chargées.
  • Visionneuse du contenu d'une cellule. L'ouverture du contenu d'une cellule propose Format JSON et Minify JSON tant que le texte est du JSON valide (nombres et chaînes sont conservés caractère par caractère), un interrupteur Wrap lines et un bouton Copy.
  • Graphique du résultat. Le bouton de graphique de la barre d'outils des requêtes dessine les lignes que la grille affiche en graphique à barres, en courbes, en secteurs ou en anneau : choisissez la colonne de l'axe x et cochez les colonnes numériques à tracer (jusqu'aux 500 premières lignes).
  • Export SQL. Parmi les formats d'export figure SQL, qui écrit des instructions INSERT INTO … VALUES …;, une par ligne, avec la protection des identificateurs et des valeurs propre à la base de données de la connexion.

Edit Data et import

  • Dupliquer la ligne copie une ligne dans un nouvel INSERT en attente (les colonnes de la clé primaire restent vides pour que la base de données les génère).
  • Aller à la ligne référencée (clic droit sur une cellule de clé étrangère) ouvre la table référencée dans Edit Data, déjà filtrée sur la ligne vers laquelle pointe la valeur ; les clés composites sont prises en charge.
  • Importer des données… (clic droit sur une table) charge un fichier CSV, TSV ou JSON (un tableau d'objets ou de tableaux). Le délimiteur est détecté ou choisi, les colonnes du fichier sont associées à celles de la table avec un aperçu des premières lignes, et les valeurs vides peuvent devenir NULL. Les lignes sont insérées dans une seule transaction : une ligne erronée (nommée dans l'erreur) laisse donc la table intacte ; jusqu'à 200 000 lignes à la fois, et jamais sur une connexion en lecture seule.

Dump, restauration et exécution de fichiers de script

Sauvegarder la table (structure et données) dans un fichier SQL et Sauvegarder la table (structure seule) dans un fichier SQL (menu Générer d'une table) écrivent le DDL de la table, suivi d'un INSERT par ligne, dans un fichier SQL — aucun programme externe n'est nécessaire. Le bouton Exécuter un script SQL depuis un fichier (restaurer une sauvegarde) de la barre d'outils des requêtes exécute un tel fichier (ou n'importe quel script SQL) instruction par instruction dans une transaction : une instruction qui échoue (nommée dans l'erreur) annule donc le reste partout où la base de données a un DDL transactionnel. Jusqu'à 48 Mo et 1 000 000 d'instructions ; refusé sur une connexion en lecture seule.

Comparer

Le bouton aux flèches de la barre d'outils des requêtes compare la connexion actuelle à une autre : soit le schéma (tables, colonnes et leurs types), soit les lignes d'une table selon la clé primaire. Le résultat est un résumé plus un script qui aligne la cible sur la source (CREATE TABLE, ADD COLUMN, changements de type, INSERT/UPDATE de lignes), ouvert dans un onglet de la connexion cible pour que vous le lisiez et l'exécutiez — comparer ne change rien. Les instructions destructrices (DROP, DELETE de lignes) ne sont écrites qu'en commentaires, sauf si vous demandez les suppressions. La nullabilité, les valeurs par défaut, les index et les contraintes ne sont pas comparés.

Requêtes planifiées

La section Requêtes planifiées de la barre de gauche exécute du SQL sur une connexion toutes les N minutes (de 1 minute à une semaine). Les planifications sont listées à gauche, avec un pied + / − ; les réglages de celle qui est sélectionnée (nom, intervalle, SQL) sont à droite, avec Exécuter maintenant, Mettre en pause / Reprendre et ses 50 dernières exécutions (état, durée et ce qu'a fait chaque instruction, ou l'erreur sur laquelle elle s'est arrêtée). Le bouton calendrier de la barre d'outils des requêtes enregistre le SQL de l'éditeur (la sélection, sinon tout le texte) comme nouvelle planification. Le planificateur vit dans le processus serveur d'OmniDB : il ne tourne donc que tant qu'OmniDB est ouvert ; une exécution arrivée à échéance pendant la fermeture a lieu une fois au démarrage suivant. Les connexions en lecture seule refusent toujours les écritures, et les connexions par tunnel SSH ou avec authentification par jeton ne peuvent pas être planifiées.

Gestion de versions (git)

Le bouton branche sous l'arborescence des extraits (et sous la liste des unités de supervision) conserve vos définitions partageables dans un dépôt git sous forme de fichiers texte : les extraits en fichiers .sql dans snippets/ (un répertoire par dossier d'extraits), les unités de supervision personnalisées en monitoring/<moteur>/*.json et les requêtes planifiées en schedules/<alias de la connexion>/*.json (l'alias et le SQL seulement — jamais une adresse ni des identifiants). Valider (commit) écrit les fichiers, supprime les fichiers .sql/.json qui ne correspondent plus à rien et les valide ; Importer depuis le dossier les relit, en créant ou en mettant à jour des définitions et sans jamais en supprimer. Une planification importée démarre en pause pour que rien ne s'exécute sans surveillance.

Git s'exécute dans OmniDB : aucune installation de git n'est nécessaire. Dans l'application de bureau, le dépôt se trouve dans un dossier du répertoire personnel d'OmniDB jusqu'à ce que vous en choisissiez un autre avec Choisir un dossier… (mémorisé entre les lancements). Sous macOS, ce dossier intégré se trouve dans le conteneur de l'application, que les autres programmes ne peuvent pas ouvrir : choisissez votre propre dossier si vous voulez pousser le dépôt avec vos outils git. Sur un serveur multi-utilisateur, vous saisissez le chemin du dossier et la fonction est limitée aux superutilisateurs. Le push et le pull restent l'affaire de vos propres outils git.
