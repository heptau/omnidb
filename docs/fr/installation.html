Installation

OmniDB propose 2 types de packages pour répondre aux besoins de chaque utilisateur :

  • Application OmniDB : lance un serveur web en arrière-plan sur un port aléatoire et fournit une fenêtre de navigateur simplifiée pour utiliser l’interface d’OmniDB sans configuration supplémentaire. L’expérience est celle d’une application de bureau.
  • Serveur OmniDB : lance un serveur web sur un port aléatoire, ou sur un port spécifié par l’utilisateur. L’utilisateur doit s’y connecter via un navigateur web. Fournit une gestion des utilisateurs, idéale pour être hébergée sur un serveur du réseau des utilisateurs.

L’application et le serveur peuvent tous deux être installés sur la même machine.

Application OmniDB

Important : le dépôt d’origine https ://github.com/OmniDB/OmniDB/releases ne contient que d’anciennes versions (jusqu’à environ 2020) et n’est plus maintenu — consultez Anciennes fonctionnalités et historique pour savoir ce qui a changé depuis.

Pour les versions actuelles, utilisez la page des versions du projet relancé. Depuis la réécriture en Go, chaque version est une archive unique et autonome par plateforme — pas d’installateur, pas de runtime séparé à installer au préalable :

  • macOS (Apple Silicon ou Intel) : OmniDB-<version>-macOS-osx-arm64.zip / OmniDB-<version>-macOS-osx-x64.zip
  • Linux x64 : OmniDB-<version>-linux-x64.tar.gz
  • Windows x64 : OmniDB-<version>-win-x64.zip

Décompressez (ou désarchivez) l’archive correspondant à votre plateforme et exécutez l’application/binaire OmniDB qu’elle contient — c’est toute l’installation. Les versions Linux et Windows sont produites par la CI à chaque version, mais n’ont pas encore été vérifiées sur du matériel réel, contrairement à la version macOS ; si vous rencontrez un problème spécifique à l’une de ces plateformes, merci d’ouvrir un ticket.

Installation via Homebrew (macOS uniquement – recommandé)

Pour les utilisateurs macOS qui préfèrent utiliser un gestionnaire de paquets, OmniDB est disponible via un tap Homebrew personnalisé :

# Installer la dernière version :
brew install --cask heptau/tap/omnidb
# Pour mettre à jour ultérieurement :
brew upgrade heptau/tap/omnidb

Homebrew téléchargera automatiquement le bon ZIP pour votre architecture (Apple Silicon ou Intel), le décompressera et placera OmniDB.app dans votre dossier Applications.

La définition du cask est maintenue ici : heptau/homebrew-tap – omnidb.rb

Téléchargement direct (toutes plateformes)

Ouvrez la dernière version et téléchargez, dans sa section Assets, l’archive correspondant à votre système/architecture parmi la liste ci-dessus. Les noms des fichiers de version incluent le numéro de version, il n’existe donc pas d’URL fixe « toujours la dernière» à lier directement — passez toujours par la page des versions elle-même.

Décompressez l’archive correspondant à votre plateforme et lancez l’application de la manière habituelle : sur macOS, glissez OmniDB.app dans Applications et ouvrez-la depuis Launchpad/Spotlight ou via open -a OmniDB ; sur Linux, exécutez directement le binaire OmniDB ; sur Windows, exécutez OmniDB.exe.

Serveur OmniDB

La même archive de version contient également omnidb-server — un binaire distinct, sans interface graphique, aux côtés de l’application de bureau (l’application de bureau lance en réalité ce même binaire en interne, en tant que processus enfant, en forçant le mode application). Exécutez-le directement pour obtenir le mode serveur accessible depuis un navigateur, sans aucune coquille de bureau :

user@machine:~$ ./omnidb-server
omnidb-server: listening on 127.0.0.1:52149 — open http://127.0.0.1:52149/omnidb_login/ in your browser

Par défaut, OmniDB n’écoute que sur 127.0.0.1 et choisit automatiquement un port libre. Vous pouvez spécifier les deux explicitement :

user@machine:~$ ./omnidb-server -p 8080 -H 0.0.0.0
omnidb-server: listening on 0.0.0.0:8080 — open http://0.0.0.0:8080/omnidb_login/ in your browser

Consultez Déployer omnidb-server pour l’ensemble complet des options et les configurations de déploiement recommandées (en particulier, pourquoi il est déconseillé d’exposer -H 0.0.0.0 directement à internet sans proxy inverse devant lui — il n’y a pas de prise en charge TLS intégrée).

OmniDB avec Oracle

Ni l’application ni le serveur OmniDB ne nécessitent de logiciel supplémentaire pour se connecter à Oracle — contrairement aux versions précédentes, aucune installation séparée d’Oracle Instant Client n’est nécessaire. La connectivité à Oracle est implémentée nativement (un pilote Go pur), elle fonctionne donc dès l’installation de la même manière que pour toute autre base de données prise en charge.

Base de données utilisateur d’OmniDB

Au premier lancement, le serveur comme l’application créent un fichier ~/.omnidb/omnidb-app/omnidb.db (pour l’application OmniDB) ou ~/.omnidb/omnidb-server/omnidb.db (pour le serveur OmniDB) dans le répertoire personnel de l’utilisateur, s’il n’existe pas encore — accompagné d’un compte superutilisateur par défaut admin/admin, avec lequel il est possible de se connecter immédiatement. Ce fichier est aussi appelé base de données utilisateur et contient tous les utilisateurs, connexions et autres données de l’application. S’il existe déjà (par exemple après une mise à jour), OmniDB l’utilise tel quel — il n’est jamais écrasé ni réinitialisé automatiquement.
