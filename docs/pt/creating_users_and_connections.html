Criar Utilizadores e Ligações

Iniciar sessão como o utilizador admin

O OmniDB vem apenas com o utilizador admin. Se estiver a usar a versão servidor, a primeira coisa a fazer é iniciar sessão como admin, cuja palavra-passe predefinida é admin. Na versão aplicação não precisa de iniciar sessão.

A janela seguinte é a janela inicial.

Criar outro utilizador

Clique no ícone Users (Utilizadores) no canto superior direito. Abrirá uma janela pop-up que permite ao superutilizador atual do OmniDB criar um novo utilizador do OmniDB.

Clique no botão Add new user (Adicionar novo utilizador) (o ícone de pessoa com um mais) dentro da janela pop-up. Insere uma nova linha de utilizador em branco, mostrada como (pending info) (informação pendente) até que a preencha.

Preencha o nome de utilizador e a palavra-passe. Assinale se pretende que este novo utilizador seja superutilizador. Esta janela de gestão de utilizadores só é visível para superutilizadores. Quando terminar, clique no botão Save (Guardar) dentro da janela pop-up.

Pode criar quantos utilizadores quiser, editar utilizadores existentes e também eliminar utilizadores clicando na cruz vermelha na coluna de ações. Agora pode terminar sessão clicando no botão Sign Out (Terminar Sessão) no canto superior direito.

Criar ligações

O OmniDB suporta PostgreSQL, MySQL, MariaDB, Oracle e SQLite.

Vamos agora criar uma ligação a uma base de dados PostgreSQL, uma ligação a uma base de dados Oracle e uma ligação a uma base de dados MariaDB. Para criar as ligações tem de clicar no botão New Connection (Nova Ligação) e depois escolher o tipo de ligação e preencher os restantes campos. Depois de preencher todos os campos de ambas as ligações, clique no botão Save (Guardar).

Para cada ligação existe uma coluna Actions (Ações) onde pode eliminar, testar e selecionar essa ligação. Vá em frente e teste a ligação PostgreSQL.

Repare que aparece uma janela pop-up com a mensagem fe_sendauth: no password supplied. Isto acontece porque o OmniDB não armazena a palavra-passe do utilizador da base de dados em disco. Não tendo nenhuma palavra-passe disponível, o OmniDB tentará ligar-se sem uma, tentando assim tirar partido de métodos de autenticação automática que possam estar em vigor: o método trust, o ficheiro .pgpass, e assim por diante. Como o servidor de base de dados responde com um erro que não permite a ligação do utilizador, o OmniDB entende que é necessária uma palavra-passe e pede-a ao utilizador. Quando o utilizador escreve uma palavra-passe nesta janela pop-up, a palavra-passe é encriptada e armazenada em memória.

Depois de escrever a palavra-passe e premir Enter, se a ligação à base de dados for bem-sucedida, verá uma janela pop-up de confirmação.

Mas, se tiver algum tipo de problema ao ligar-se à sua base de dados PostgreSQL, a mesma janela pop-up continuará a mostrar o erro obtido pelo OmniDB.

Usar túneis SSH

O OmniDB permite ao utilizador ligar-se a qualquer base de dados remota através de túneis SSH. O utilizador precisa de preencher a informação do túnel SSH em cada ligação na Grelha de Ligações.

  • SSH Server (Servidor SSH): O servidor ao qual se está a ligar via SSH;
  • SSH Port (Porta SSH): A porta do servidor SSH (a predefinição é 22, mas pode ser qualquer número de porta);
  • SSH User (Utilizador SSH): O nome de utilizador do sistema operativo que usa para se ligar ao servidor SSH;
  • Password/Passphrase (Palavra-passe/Frase-passe): A palavra-passe do utilizador do sistema operativo (ou a frase-passe da chave abaixo). Se preencher o campo SSH Key Text File (Ficheiro de Texto da Chave SSH), a palavra-passe é opcional;
  • SSH Key Text File (Ficheiro de Texto da Chave SSH): O conteúdo da chave privada SSH local que pode usar para se ligar ao servidor SSH. Se preencher este campo, também pode preencher o campo Password/Passphrase, mas neste caso será a frase-passe da chave privada SSH.

Note que toda a informação é armazenada encriptada na Base de Dados de Utilizador local do OmniDB.
