Utilizadores Ligados

A secção Utilizadores ligados mostra quem está neste momento ligado a um servidor de base de dados — backends do PostgreSQL, threads do MySQL/MariaDB, sessões do Oracle e do SQL Server, attachments do Firebird —, o que cada um está a fazer, e permite-lhe terminar qualquer um deles. Substitui as antigas entradas Backends/Lista de processos/Sessões, específicas de cada motor, do menu de contexto da árvore da base de dados.

Suportados: PostgreSQL, MySQL, MariaDB, Oracle, SQL Server e Firebird. O SQLite não tem esse conceito e mostra A visualização de utilizadores ligados não é suportada para ligações ….

Abrir a secção

Clique no ícone Utilizadores ligados na barra esquerda. Tal como Monitorização, Notificações e Permissões, trabalha sobre uma ligação já aberta na secção Base de dados: a faixa de separadores de ligação abertos é mostrada no topo, e a lista pertence ao separador selecionado. Sem nenhuma ligação aberta, mostra Nenhuma ligação aberta.

A lista é carregada quando entra na secção e sempre que muda para outro separador de ligação; não se atualiza sozinha. Para a recarregar, clique com o botão direito na grelha e escolha Atualizar. O número de linhas é mostrado por cima da grelha (Número de registos: …).

Colunas

As colunas estão agrupadas de forma compacta (por exemplo, um ID por baixo de um nome, ou endereço e porta numa só linha); passar o rato sobre um cabeçalho de coluna explica o que mostra e de que coluna do catálogo provém.

  • PostgreSQL (pg_stat_activity): PID, Base de dados, Utilizador, Cliente, Aplicação, Início do processo / Início da transação, Início da consulta / Última alteração de estado, À espera de, Estado, ID da transação, ID da consulta, Tipo de processo.
  • MySQL/MariaDB (lista de processos): Utilizador (com o ID da ligação), Anfitrião, Base de dados, Comando, Tempo (s), Estado.
  • Oracle (v$session): SID (com Serial#), Utilizador, Estado, Esquema, Cliente, Programa, Módulo / ação, Info do cliente, Hora de início de sessão, Inativo (s), ID de SQL, À espera de, SID bloqueante.
  • SQL Server (sessões de utilizador): ID de sessão, Nome de início de sessão, Anfitrião, Programa, Estado.
  • Firebird (mon$attachments, sem o attachment do próprio OmniDB): ID de ligação, Utilizador, Endereço remoto, Estado.

No PostgreSQL e no Oracle, os processos de segundo plano/do sistema estão ocultos por predefinição; assinale Mostrar processos do sistema por cima da grelha para os incluir (a caixa de seleção só aparece quando existem linhas desse tipo).

Ver a consulta de uma sessão

No PostgreSQL, MySQL e MariaDB, clicar numa linha abre um painel Texto da consulta por baixo da grelha com a instrução que essa sessão está a executar (ou executou por último), com realce de sintaxe e só de leitura. A partir daí pode copiá-la, ou usar Abrir num novo separador de consulta para continuar a trabalhar com ela num separador de consulta normal, por exemplo para executar Explain sobre ela.

Terminar uma sessão

Clique com o botão direito numa linha e escolha Terminar. Depois de confirmar, o OmniDB termina essa sessão da forma própria do motor — pg_terminate_backend() no PostgreSQL, KILL no MySQL/MariaDB e no SQL Server, ALTER SYSTEM KILL SESSION … IMMEDIATE no Oracle, eliminando a linha de mon$attachments no Firebird — e recarrega a lista. Isto requer o privilégio correspondente no servidor de base de dados. O mesmo menu de contexto oferece também Copiar e Ver conteúdo para a célula clicada.
