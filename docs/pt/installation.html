Instalação

O OmniDB disponibiliza 2 tipos de pacotes para se adaptar às necessidades de cada utilizador:

  • OmniDB Application: Executa um servidor web numa porta aleatória em segundo plano, e disponibiliza uma janela de browser simplificada para usar a interface do OmniDB sem qualquer configuração adicional. Parece exatamente uma aplicação de ambiente de trabalho.
  • OmniDB Server: Executa um servidor web numa porta aleatória, ou numa porta especificada pelo utilizador. O utilizador precisa de se ligar a ele através de um browser. Disponibiliza gestão de utilizadores, ideal para ser alojado num servidor nas redes dos utilizadores.

Tanto a aplicação como o servidor podem ser instalados na mesma máquina.

OmniDB Application

Importante: O repositório original https://github.com/OmniDB/OmniDB/releases contém apenas versões antigas (até cerca de 2020) e já não é mantido — consulte Funcionalidades Legadas e Histórico para saber o que mudou desde então.

Para as versões atuais, use a página de releases do projeto retomado. Desde a reescrita em Go, cada release é um único arquivo autocontido por plataforma — sem instalador, sem runtime separado a instalar primeiro:

  • macOS (Apple Silicon ou Intel): OmniDB-<version>-macOS-osx-arm64.zip / OmniDB-<version>-macOS-osx-x64.zip
  • Linux x64: OmniDB-<version>-linux-x64.tar.gz
  • Windows x64: OmniDB-<version>-win-x64.zip

Descompacte o arquivo (zip ou tar) para a sua plataforma e execute a aplicação/binário OmniDB lá dentro — é toda a instalação. As builds para Linux e Windows são geradas pelo CI em cada release, mas ainda não foram verificadas em hardware real, ao contrário da build para macOS; se encontrar algum problema específico da plataforma numa delas, por favor abra uma issue.

Instalação via Homebrew (apenas macOS – recomendado)

Para utilizadores de macOS que preferem usar um gestor de pacotes, o OmniDB está disponível através de um tap Homebrew personalizado:

# Instalar a versão mais recente:
brew install --cask heptau/tap/omnidb
# Para atualizar mais tarde:
brew upgrade heptau/tap/omnidb

O Homebrew irá transferir automaticamente o ZIP correto para a sua arquitetura (Apple Silicon ou Intel), descompactá-lo e colocar OmniDB.app na sua pasta Applications.

A definição do cask é mantida aqui: heptau/homebrew-tap – omnidb.rb

Transferência direta (todas as plataformas)

Abra a última release e transfira o arquivo correspondente ao seu sistema operativo/arquitetura da lista acima, a partir da respetiva secção Assets. Os nomes dos ficheiros de release incluem o número da versão, pelo que não existe um URL fixo «sempre a mais recente» a que se possa ligar diretamente — vá sempre através da própria página de releases.

Descompacte o arquivo para a sua plataforma e abra a aplicação da forma habitual: no macOS, arraste OmniDB.app para Applications e abra-o a partir do Launchpad/Spotlight ou com open -a OmniDB; no Linux, execute o binário OmniDB diretamente; no Windows, execute OmniDB.exe.

OmniDB Server

O mesmo arquivo de release também contém o omnidb-server — um binário separado, sem interface gráfica, ao lado da aplicação de ambiente de trabalho (a aplicação de ambiente de trabalho na verdade inicia este mesmo binário internamente, como processo filho, forçando o modo aplicação). Execute-o diretamente para o modo servidor acessível pelo browser, sem qualquer camada de ambiente de trabalho envolvida:

user@machine:~$ ./omnidb-server
omnidb-server: listening on 127.0.0.1:52149 — open http://127.0.0.1:52149/omnidb_login/ in your browser

Por predefinição, o OmniDB escuta apenas em 127.0.0.1 e escolhe automaticamente uma porta livre. Pode especificar ambos explicitamente:

user@machine:~$ ./omnidb-server -p 8080 -H 0.0.0.0
omnidb-server: listening on 0.0.0.0:8080 — open http://0.0.0.0:8080/omnidb_login/ in your browser

Consulte Implementar o omnidb-server para o conjunto completo de opções e configurações de implementação recomendadas (em particular, por que razão expor -H 0.0.0.0 diretamente à internet sem um proxy inverso à frente é desaconselhado — não existe suporte de TLS incorporado).

OmniDB com Oracle

Nem a aplicação nem o servidor OmniDB requerem qualquer software adicional para se ligar ao Oracle — ao contrário de versões anteriores, não é necessária qualquer instalação separada do Oracle Instant Client. A conectividade Oracle está implementada nativamente (um driver Go puro), pelo que funciona da mesma forma imediatamente, tal como qualquer outra base de dados suportada.

Base de Dados de Utilizador do OmniDB

Na primeira execução, tanto o servidor como a aplicação criam um ficheiro ~/.omnidb/omnidb-app/omnidb.db (para a aplicação OmniDB) ou ~/.omnidb/omnidb-server/omnidb.db (para o servidor OmniDB) na pasta pessoal do utilizador, caso ainda não exista — juntamente com uma conta de superutilizador admin/admin predefinida, pronta para iniciar sessão de imediato. Este ficheiro também é chamado a base de dados de utilizador e contém todos os utilizadores, ligações e outros dados da aplicação. Se já existir (por exemplo, após uma atualização), o OmniDB usa-o tal como está — nunca é substituído ou reposto automaticamente.
