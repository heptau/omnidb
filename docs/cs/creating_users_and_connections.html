Vytváření uživatelů a připojení

Přihlášení jako uživatel admin

OmniDB obsahuje pouze uživatele admin. Pokud používáte serverovou verzi, první věc, kterou musíte udělat, je přihlásit se jako admin, výchozí heslo je admin. V aplikační verzi se přihlašovat nemusíte.

Následující okno je počáteční okno.

Vytvoření dalšího uživatele

Klikněte na ikonu Users (Uživatelé) v pravém horním rohu. Otevře se vyskakovací okno, které umožňuje aktuálnímu superuživateli OmniDB vytvořit nového uživatele OmniDB.

Klikněte uvnitř vyskakovacího okna na tlačítko Add new user (Přidat nového uživatele) (ikona postavičky s plus). Vloží se nový, prázdný řádek uživatele, zobrazený jako (pending info) (čeká na vyplnění), dokud ho nevyplníte.

Vyplňte uživatelské jméno a heslo. Zaškrtněte, zda má být tento nový uživatel superuživatelem. Toto okno pro správu uživatelů vidí pouze superuživatelé. Až budete hotovi, klikněte uvnitř vyskakovacího okna na tlačítko Save (Uložit).

Můžete vytvořit tolik uživatelů, kolik chcete, upravovat existující uživatele a také mazat uživatele kliknutím na červený křížek ve sloupci akcí. Nyní se můžete odhlásit kliknutím na tlačítko Sign Out (Odhlásit se) v pravém horním rohu.

Vytváření připojení

OmniDB podporuje PostgreSQL, MySQL, MariaDB, Oracle a SQLite.

Nyní vytvoříme jedno připojení k databázi PostgreSQL, jedno připojení k databázi Oracle a jedno připojení k databázi MariaDB. Pro vytvoření připojení musíte kliknout na tlačítko New Connection (Nové připojení) a poté zvolit typ připojení a vyplnit ostatní pole. Po vyplnění všech polí pro obě připojení klikněte na tlačítko Save (Uložit).

U každého připojení je sloupec Actions (Akce), kde je můžete mazat, testovat a vybírat. Zkuste nyní otestovat připojení k PostgreSQL.

Všimněte si, že se objeví vyskakovací okno se zprávou fe_sendauth: no password supplied. Děje se to proto, že OmniDB neukládá heslo uživatele databáze na disk. Bez hesla po ruce se OmniDB pokusí připojit bez něj a tím se pokusí využít automatické metody ověřování, které mohou být nastavené: metodu trust, soubor .pgpass a podobně. Jelikož databázový server odpoví chybou, která uživateli neumožní se připojit, OmniDB pochopí, že je vyžadováno heslo, a vyžádá si ho od uživatele. Když uživatel zadá heslo do tohoto vyskakovacího okna, heslo se zašifruje a uloží do paměti.

Poté, co zadáte heslo a stisknete Enter, pokud je připojení k databázi úspěšné, uvidíte potvrzovací vyskakovací okno.

Pokud však máte jakékoli potíže s připojením k databázi PostgreSQL, ve stejném vyskakovacím okně se zobrazí chyba, kterou OmniDB obdržela.

Použití SSH tunelů

OmniDB umožňuje uživateli připojit se k libovolné vzdálené databázi prostřednictvím SSH tunelů. Uživatel musí vyplnit informace o SSH tunelu u každého připojení v mřížce připojení (Connections Grid).

  • SSH Server: Server, ke kterému se připojujete přes SSH;
  • SSH Port: Port SSH serveru (výchozí je 22, ale může to být jakékoli číslo portu);
  • SSH User: Uživatelské jméno v operačním systému, které používáte pro připojení k SSH serveru;
  • Password/Passphrase: Heslo uživatele operačního systému (nebo přístupová fráze ke klíči níže). Pokud vyplníte pole SSH Key Text File, heslo je volitelné;
  • SSH Key Text File: Obsah lokálního privátního SSH klíče, který lze použít pro připojení k SSH serveru. Pokud vyplníte toto pole, můžete zároveň vyplnit pole Password/Passphrase, ale v tomto případě půjde o přístupovou frázi k privátnímu SSH klíči.

Uvědomte si prosím, že všechny tyto informace jsou uloženy zašifrovaně ve vaší lokální uživatelské databázi OmniDB.

Při používání SSH tunelů musíte také odpovídajícím způsobem vyplnit všechna pole databáze. Místo toho, aby byla relativní vůči serveru OmniDB, budou relativní vůči SSH serveru. To lze provést ve 2 scénářích, jak je vysvětleno níže.
