Creazione di utenti e connessioni

Accesso come utente admin

OmniDB viene fornito solo con l’utente admin. Se stai usando la versione server, la prima cosa da fare è accedere come admin, la password predefinita è admin. Non è necessario accedere nella versione app.

La finestra successiva è la finestra iniziale.

Creazione di un altro utente

Fai clic sull’icona Users nell’angolo in alto a destra. Si aprirà un popup che permette al super user OmniDB attuale di creare un nuovo utente OmniDB.

Fai clic sul pulsante Add new user (l’icona a forma di persona con il segno più) all’interno del popup. Verrà inserita una nuova riga utente vuota, mostrata come (pending info) finché non viene compilata.

Compila lo username e la password. Seleziona la casella se vuoi che questo nuovo utente sia un super user. Questa finestra di gestione utenti è visibile solo ai super user. Quando hai finito, fai clic sul pulsante Save all’interno del popup.

Puoi creare tutti gli utenti che vuoi, modificare gli utenti esistenti e anche eliminare utenti facendo clic sulla croce rossa nella colonna delle azioni. Ora puoi disconnetterti facendo clic sul pulsante Sign Out nell’angolo in alto a destra.

Creazione delle connessioni

OmniDB supporta PostgreSQL, MySQL, MariaDB, Oracle e SQLite.

Creeremo ora una connessione a un database PostgreSQL, una connessione a un database Oracle e una connessione a un database MariaDB. Per creare le connessioni devi fare clic sul pulsante New Connection e poi scegliere il tipo di connessione e compilare gli altri campi. Dopo aver compilato tutti i campi per entrambe le connessioni, fai clic sul pulsante Save.

Per ogni connessione c’è una colonna Actions dove puoi eliminarla, testarla e selezionarla. Vai avanti e testa la connessione PostgreSQL.

Nota che appare un popup con il messaggio fe_sendauth: no password supplied. Questo accade perché OmniDB non memorizza su disco la password dell’utente del database. Non avendo a disposizione alcuna password, OmniDB proverà a connettersi senza, cercando così di sfruttare eventuali metodi di autenticazione automatica disponibili: metodo trust, file .pgpass, e così via. Poiché il server del database risponde con un errore che non permette all’utente di connettersi, OmniDB capisce che è richiesta una password e la chiede all’utente. Quando l’utente digita una password in questo popup, la password viene cifrata e memorizzata in memoria.

Dopo aver digitato la password e premuto Invio, se la connessione al database ha successo vedrai un popup di conferma.

Ma se hai problemi di qualsiasi tipo nel connetterti al tuo database PostgreSQL, lo stesso popup continuerà a mostrare l’errore ricevuto da OmniDB.

Uso dei tunnel SSH

OmniDB permette all’utente di connettersi a qualsiasi database remoto tramite tunnel SSH. L’utente deve compilare le informazioni del tunnel SSH in ogni connessione nella Connections Grid.

  • SSH Server: Il server a cui ti connetti tramite SSH;
  • SSH Port: La porta del server SSH (il valore predefinito è 22, ma può essere qualsiasi numero di porta);
  • SSH User: Il nome utente del sistema operativo che usi per connetterti al server SSH;
  • Password/Passphrase: La password dell’utente del sistema operativo (oppure la passphrase per la chiave sottostante). Se compili il campo SSH Key Text File, la password è opzionale;
  • SSH Key Text File: Il contenuto della chiave privata SSH locale che puoi usare per connetterti al server SSH. Se compili questo campo, puoi anche compilare il campo Password/Passphrase, ma in questo caso sarà la passphrase per la chiave privata SSH.

Nota che tutte le informazioni sono memorizzate in forma cifrata nel tuo User Database locale di OmniDB.
