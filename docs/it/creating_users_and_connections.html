Creazione di utenti e connessioni

Accesso come utente admin

OmniDB viene fornito solo con l’utente admin. Se stai usando la versione server, la prima cosa da fare è accedere come admin, la password predefinita è admin. L’applicazione desktop non prevede alcun accesso: gira come unico utente locale, quindi tutto ciò che riguarda la gestione degli utenti descritta qui sotto lì semplicemente non c’è.

Orientarsi nell’interfaccia

L’intero spazio di lavoro si comanda dalla barra verticale di icone sul bordo sinistro della finestra: Welcome (Benvenuto), Connections (Connessioni, l’icona della spina), Database, Notify (Notifiche) e Snippets (Frammenti) in alto, e Getting Started (Per iniziare), Account (solo nella versione server) e Settings (Impostazioni, l’ingranaggio) in basso.

Creazione di un altro utente

Apri Settings (Impostazioni) in fondo alla barra, scegli la categoria Account e fai clic su Manage Users (Gestisci utenti). Quel pulsante lo vede solo un superutente: nelle impostazioni di un utente normale la sezione Account non compare affatto.

La finestra User management (Gestione utenti) elenca gli utenti esistenti. Fai clic su Add new user (Aggiungi nuovo utente, l’icona della persona con il più) per inserire una nuova riga utente vuota, mostrata come (pending info) finché non la compili. Inserisci nome utente e password, spunta Super User se il nuovo utente deve esserlo, quindi fai clic su Save (Salva). Puoi creare tutti gli utenti che vuoi, modificare quelli esistenti ed eliminarne uno facendo clic sulla croce rossa nella colonna delle azioni.

Per disconnetterti fai clic sull’icona Account (la persona in fondo alla barra) e poi su Sign out (Esci).

La sezione Connections

Fai clic sull’icona della spina nella barra. Le connessioni sono una sezione a tutti gli effetti dello spazio di lavoro, non una finestra a comparsa: una vista divisa con l’elenco delle connessioni salvate nella barra laterale a sinistra e, a destra, il modulo e i pulsanti della connessione selezionata.

Ogni riga dell’elenco mostra l’icona del motore di database, il nome della connessione e sotto l’utente@server:porta a cui punta (oppure la stringa di connessione, o la destinazione SSH per una connessione di tipo terminale). Un pallino colorato indica l’ambiente della connessione e un’icona a forma di chiave segnala una connessione che passa da un tunnel SSH.

Creazione di connessioni

OmniDB supporta PostgreSQL, MySQL, MariaDB, Oracle, MS SQL Server, Firebird e SQLite, oltre a un tipo di connessione Terminal che apre una shell SSH invece di un database.

Il pulsante + sotto l’elenco crea una connessione. Scrivi il nome nell’intestazione del modulo a destra, scegli il Connection Type (tipo di connessione) e compila la scheda Host Connection Info (dati del server): Server, Port, Database, User e, facoltativamente, User Password. Al posto dei singoli campi puoi compilare una sola Connection string (stringa di connessione, ad esempio postgresql://postgres@localhost:5432/postgres) e lasciare vuoto il resto. Al termine fai clic su Save (Salva) in alto a destra nel modulo.

Test Connection (Prova connessione), accanto, prova la connessione senza aprirla e riporta Connection successful. oppure l’errore esatto restituito dal database. Il pulsante − sotto l’elenco elimina la connessione selezionata; resta disattivato per una connessione attualmente aperta in una scheda.

Password

Il campo User Password (password utente) è facoltativo e le due possibilità si comportano in modo diverso:

  • Compilato: la password viene salvata nel database di configurazione di OmniDB e riutilizzata automaticamente ogni volta che apri la connessione. È conservata in chiaro in quel file locale, quindi trattalo come un segreto: chi può leggerlo legge anche le password che contiene.
  • Lasciato vuoto: non viene salvato nulla e OmniDB chiede la password quando apri la connessione. Quello che digiti resta solo nella memoria di sessione del server per quella connessione e sparisce alla fine della sessione.

Per PostgreSQL, al momento della connessione OmniDB cerca inoltre la password nel tuo file .pgpass, scegliendo la stessa voce che userebbe libpq: una connessione senza password salvata può quindi aprirsi senza alcuna richiesta. Nell’applicazione macOS in sandbox la finestra della password offre Grant access to .pgpass… (Concedi accesso a .pgpass): indichi il file una volta e da lì in poi ogni connessione ricava da sé la propria password.

Se il database rifiuta il tentativo, la finestra resta a schermo mostrando l’errore ricevuto da OmniDB (fe_sendauth: no password supplied, un errore di autenticazione, un server non raggiungibile e così via), così puoi correggere la password e riprovare.

Importare connessioni da .pgpass

L’icona di importazione file, accanto ai pulsanti + e −, legge un file .pgpass e crea una connessione PostgreSQL per ogni riga concreta che contiene, come semplice stringa postgresql://utente@host:porta/db senza password salvata: l’idea è continuare ad autenticarsi da quel file invece di copiare password dentro OmniDB. Le righe con caratteri jolly (*) vengono saltate, così come quelle che corrispondono già a una connessione esistente.

Organizzare l’elenco

  • Ordine: trascina una riga in qualsiasi posizione dell’elenco. La disposizione viene salvata per ciascun utente e sopravvive sia a un ricaricamento sia a un riavvio. Le connessioni create in seguito si aggiungono in fondo.
  • Gruppi: il selettore in cima alla barra laterale limita l’elenco a un solo gruppo. + Group crea un gruppo e il pulsante … accanto offre Rename (Rinomina), Manage Connections (Gestisci connessioni: trasforma le righe in caselle di spunta con cui scegliere quali connessioni appartengono al gruppo, da confermare con Save changes) ed Delete (Elimina).
  • Connessioni pubbliche: l’interruttore Public connection? (Connessione pubblica?) nel modulo rende la connessione utilizzabile da tutti gli altri utenti di OmniDB. L’interruttore Public (n) in fondo alla barra laterale mostra o nasconde nel tuo elenco le connessioni pubbliche di altri utenti.
  • Ambiente: contrassegnare una connessione come Production, UAT, Development o Archive colora il suo pallino nell’elenco e il bordo della sua scheda aperta: è soprattutto un accorgimento di sicurezza, perché prendere la scheda sbagliata si veda subito.

Aprire una connessione

Fai clic su Connect (Connetti) nel modulo, oppure semplicemente doppio clic su una riga dell’elenco, e OmniDB la apre in una nuova scheda esterna di connessione (Connection Outer Tab), come vedremo nel prossimo capitolo. Il clic destro su una riga apre un menu contestuale (Connect/Edit/Delete — Delete non compare per una connessione già aperta), mentre il clic destro su uno spazio vuoto dell’elenco propone New Connection/Refresh.

Uso dei tunnel SSH

OmniDB consente di connettersi a qualsiasi database remoto attraverso tunnel SSH. Spunta Use SSH tunnel (Usa tunnel SSH) nel modulo della connessione: questo abilita i campi sottostanti:

  • SSH Server: il server a cui ti connetti via SSH;
  • SSH Port: la porta del server SSH (l’impostazione predefinita è 22, ma può essere una porta qualsiasi);
  • SSH User: il nome utente del sistema operativo con cui ti connetti al server SSH;
  • Password/Passphrase (Password / frase di accesso): la password dell’utente del sistema operativo (o la frase di accesso della chiave qui sotto). Se lo lasci vuoto, OmniDB la chiede a ogni apertura del tunnel senza memorizzarla. Se compili il campo SSH Key Text File, la password è facoltativa;
  • SSH Key Text File (File della chiave SSH): il contenuto della chiave SSH privata locale con cui puoi connetterti al server SSH. OmniDB legge il file che scegli e ne salva il testo, non il file. Se compili questo campo puoi compilare anche Password/Passphrase, che però in questo caso sarà la frase di accesso della chiave privata SSH.

Tutto ciò che salvi qui — password SSH, frase di accesso e testo della chiave — finisce nello stesso database di configurazione locale di OmniDB delle password dei database, e nella stessa forma non cifrata.
