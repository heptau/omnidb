Scrittura di query SQL

Il tipo più comune di scheda interna è la Scheda Query, che contiene i seguenti elementi:

  • 1) Intestazione della Scheda: Puoi vedere il nome della scheda e un’icona per chiuderla. Se c’è una query in esecuzione nella scheda, vedrai un indicatore. Se la scheda termina l’esecuzione e stai lavorando su una scheda diversa, ti verrà mostrato un indicatore verde. Facendo doppio clic sul nome della scheda, potrai rinominarla.
  • 2) Aggiungi Scheda: Puoi aggiungere rapidamente un’altra scheda interna facendo clic sull’icona più.
  • 3) Editor SQL: Editor SQL completo con evidenziazione della sintassi SQL, Trova e Sostituisci (Ctrl-F e Ctrl-H) e un componente di autocompletamento, spiegato più avanti. Vedi Scorciatoie da tastiera dell’editor per l’elenco completo delle scorciatoie dell’editor (selezione, cursori multipli, navigazione, raggruppamento del codice, ecc.).
  • 4) Esegui: Il testo contenuto nell’Editor SQL verrà eseguito sul database attualmente attivo quando fai clic su questo pulsante (o premi la scorciatoia, Alt-Q per impostazione predefinita). Se nell’Editor SQL è presente del testo selezionato, verrà eseguito solo il testo selezionato. Una volta che il comando è in esecuzione, verrà mostrato un pulsante rosso Annulla, che ti permette di annullare l’esecuzione (oppure usando la scorciatoia, Alt-C per impostazione predefinita).
  • 5) Indenta SQL: Questo pulsante formatta in modo ordinato qualsiasi codice SQL scritto nell’editor SQL (scorciatoia Alt-S per impostazione predefinita, Ctrl-S su macOS).
  • 6) Cronologia Comandi: Tutti i comandi eseguiti sul database corrente vengono memorizzati nella Cronologia Comandi, accessibile facendo clic su questo pulsante. Potrai anche filtrare per data e testo per trovare un comando SQL di cui hai bisogno.
  • 7) Spiega (solo PostgreSQL): Richiama la tua query SQL su PostgreSQL anteponendo EXPLAIN. I risultati verranno mostrati in forma testuale e grafica nella scheda Spiega (per maggiori dettagli, vedi Visualizzazione dei piani di query).
  • 8) Spiega ed Esegui (solo PostgreSQL): Come il pulsante Spiega, ma richiama la query SQL con EXPLAIN ANALYZE, che eseguirà effettivamente la query.
  • 9) Autocommit (solo PostgreSQL): Quando abilitato, ogni query eseguita verrà confermata (commit) sul database. Quando disabilitato, OmniDB avvia una transazione e, all’esecuzione di una query, l’interfaccia mostrerà pulsanti che permettono all’utente di eseguire Commit o Rollback. L’utente può anche mantenere la transazione aperta ed eseguire altri comandi.
  • 10) Stato del Backend (solo PostgreSQL): Quando apri una nuova Scheda Query, lo stato è «Non Connesso», poiché OmniDB non ha ancora avviato un backend PostgreSQL. Quando esegui la prima query, OmniDB avvia un nuovo backend e lo mantiene collegato alla Scheda Query (a ogni Scheda Query viene assegnato il proprio backend). Lo stato del backend (idle, active, idle in transaction, ecc.) verrà mostrato in questo campo. Quando chiudi la Scheda Query, OmniDB termina il backend.
  • 11) Tipo di File di Esportazione: Può essere CSV, TSV, XLSX, JSON, XML o Markdown.
  • 12) Esporta su File: Facendo clic su questo pulsante, OmniDB esegue la query corrente ed esporta i risultati in un file. Nell’app desktop, si apre una finestra di dialogo nativa «Salva con nome» che ti permette di scegliere dove salvarlo direttamente. Quando invece esegui OmniDB in modalità browser tramite OmniDB Server, il file viene prima scritto nella cartella temporanea del server, e l’interfaccia mostra poi un link per scaricarlo tramite il browser.
  • 13) Risultati Dati: Se la query è una SELECT, verrà mostrata una griglia con i risultati. Se la query è una DML o DDL, verrà mostrato il messaggio restituito dal RDBMS.
  • 14) Messaggi (solo PostgreSQL): Qui verranno mostrati eventuali messaggi (come quelli generati dal comando RAISE NOTICE).
  • 15) Vista Spiega (solo PostgreSQL): Mostra un componente completo per visualizzare il piano di esecuzione di PostgreSQL in forma testuale o grafica.

Una volta eseguite, le schede vengono salvate anche nel database utente di OmniDB (titolo e contenuti), quindi la prossima volta che apri OmniDB le vedrai tutte aperte. Inoltre, ogni comando eseguito in una Scheda Query viene salvato nella tua Cronologia Comandi e anche nel file omnidb.log.

Completamento automatico SQL

L’editor SQL ha una funzionalità che aiuta molto nella creazione di nuove query: il completamento automatico del codice SQL. Con questa funzionalità è possibile completare automaticamente le colonne contenute in una tabella referenziata tramite un alias.
